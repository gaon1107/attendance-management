# Research: 저조도 오탐 대응 — 밝기 안내(①) vs 모델별 차등 기준(②) (2026-07-11)

## 요청 배경 (사용자 야간 실측)
- 어두운 곳에서 **진짜 얼굴이 "위조 의심"으로 오탐**. 작을수록 심함. 창문 열어 밝게 하면 정상 판정.
- 실측 데이터(진짜 얼굴, 기준값 80%·AND):
  | 조건 | 모델 A(V1SE) | 모델 B(V2) | 유효(낮은쪽) | 결과 |
  |---|---|---|---|---|
  | 어두움+작은얼굴(43%) | 63~69% | 85~89% | 63% | 위조 의심(오탐) |
  | 어두움(40%) | 72~84% | 98~99% | 72% | 위조 의심(오탐) |
  | 밝게(창문,37%) | 95~97% | 99% | 95% | 진짜 ✓ |
- **핵심 원인**: 저조도에서 무너지는 건 **모델 A뿐**. 모델 A는 얼굴 주변을 4.0배로 넓게 보는데(모델 B는 2.7배), 어두운 넓은 영역이 노이즈라 판단 실패. 모델 B는 어두워도 85~99% 안정. AND는 "둘 중 낮은 값"이라 약한 모델 A가 진짜를 끌어내림.

## 판정 로직 위치 확인 (전수 확인 결과)
- **판정은 전부 클라이언트(app/DemoClient.tsx)에서** 이뤄진다:
  - effFrame(f) = mode==="and" ? min(A,B) : (A+B)/2  [DemoClient.tsx:190]
  - judge(score) = score >= threshold  [187]
- **서버(app/actions/liveness.ts)는 원점수(모델 A/B realProb)만 반환**, 판정 안 함.
- lib/liveness.ts(analyzeFace)는 점수 계산만. **이식 대상 파일이며 무수정 유지 가능.**

## 방안 ① 밝기 안내
**개념**: 촬영한 얼굴 영역이 너무 어두우면 위조로 판정하지 않고 "화면이 어둡습니다 — 더 밝은 곳에서 촬영해 주세요" 안내(기존 tooSmall과 동일 패턴). 어두운 진짜를 위조로 몰지 않음.
- **밝기 측정 위치**: 서버가 얼굴 rect를 알고 있으므로 서버에서 얼굴 영역 평균 밝기(0~255) 계산이 정확(배경 영향 배제). lib/texture.ts가 이미 얼굴 중앙을 흑백 크롭+평균(mean) 계산 → **거의 공짜로 재사용 가능**. 또는 소형 순수함수 신설.
- **수정 파일**: lib/texture.ts(또는 신규 lib/quality.ts) — 밝기 반환 / app/actions/liveness.ts — 밝기 반환 필드 추가 / app/DemoClient.tsx — 밝기 표시 + "밝기 기준" 슬라이더 + 미달 시 안내(tooSmall과 동형).
- **영향 범위**: 기존 tooSmall 경로와 같은 자리에 한 겹 추가. lib/liveness.ts·gaonfr.ts 무수정.
- **캘리브레이션**: 밝기 기준값은 실측 필요(어두운 오탐 건 밝기 vs 밝은 정상 건 밝기). 질감 때와 달리 **밝기는 신호가 명확**(어두운 건 낮고 밝은 건 높음)해서 선 긋기 쉬움. 슬라이더로 라이브 튜닝(얼굴 크기 기준과 동일 UX).
- **장점**: 오탐(진짜→위조)을 원천 차단, 안전. 계산 초경량. **단점**: 재촬영 유도(약간의 마찰). 아주 어두운 환경 자체는 해결 못 함(조명 필요).

## 방안 ② 모델별 차등 기준
**개념**: 단일 기준값 대신 모델별 기준. 어둠에 약한 **모델 A는 낮게(예 60%)**, 어둠에 강하고 위조를 잘 잡는 **모델 B는 높게(예 85%)**. 어두운 진짜(A 63~84%)는 통과, 위조는 모델 B가 차단.
- **수정 위치**: **app/DemoClient.tsx의 effFrame/판정만** (클라이언트 판정). 프레임별 "A ≥ thA AND B ≥ thB", 전 장 통과.
- **수정 파일**: app/DemoClient.tsx 단 하나. 서버·lib 무수정.
- **영향 범위**: 판정식만 교체. 이력 재판정도 원점수 보관 중이라 그대로 동작. 화면에 슬라이더 1개→2개(모델 A/B 기준) 또는 고급옵션.
- **위조 위험(반드시 검증)**: 모델 A 기준을 낮추면 "모델 A로만 잡히던 위조"가 새어나갈 수 있음. 실측 밝은 위조에서 모델 A 최저 4.5~83%, 모델 B 최저 3.9~83%로 둘 다 위조를 잡는 편이지만, **모델 A 기준 하향이 특정 위조를 통과시키지 않는지 어두운 조건 위조까지 실측 검증 필요**.
- **장점**: 재촬영 마찰 없음. 데이터에 정확히 부합(모델 B 주력). **단점**: 조절 손잡이가 늘어 사용자 혼란 여지. 위조 놓침 위험이 ①보다 큼 → 검증 부담.

## 결론·추천 (계획 시 고려)
- 두 방안은 **상호 보완**: ①은 "정보가 없는 캄캄한" 경우를 재촬영으로 돌리고, ②는 "적당히 어두워 모델 B는 살아있는" 경우를 통과시킴.
- **추천 순서: ① 밝기 안내 먼저** (오탐 0, 안전, 이식 시 조명 안내와 결합). 그 후 ①으로도 남는 애매한 구간에 ② 적용(검증 후).
- 단, 근본 해결은 **근태 단말기 옆 조명 확보**. 소프트웨어는 보조.
- 두 방안 모두 lib/liveness.ts·gaonfr.ts 무수정으로 구현 가능(위험 낮음).
