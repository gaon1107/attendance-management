## 1. 접근 방식 (+이유)
저조도에서 **모델 A(V1SE)만 무너지고 모델 B(V2)는 든든**한 실측 패턴을 이용한다. 판정 방식에 **"모델별 차등"을 세 번째 옵션으로 추가** — 모델 A는 낮은 기준(예 60%), 모델 B는 높은 기준(예 85%)을 따로 적용. 어두운 진짜(A가 60~84%로 떨어져도)는 통과, 위조는 모델 B가 차단.

- **왜 옵션(토글)으로?** 기존 "평균/AND"를 건드리지 않고 새 방식만 추가 → 기존 판정이 깨질 위험 0. 켜야만 작동(opt-in). 밝기 안내를 "기본 꺼짐"으로 넣은 것과 같은 안전 철학.
- **왜 화면만 고치나?** 판정은 전부 DemoClient.tsx에서 이뤄짐(서버·lib은 원점수만 제공, 전수 확인). 근태 이식 대상 파일(lib/*)·서버 무수정.

## 3. 🛡️ 사이드 이펙트 방어 (가장 중요)
현재 판정은 "대표점수 eff ≥ threshold" 숫자 비교. 이를 **판정 방식별 통과 여부(framePass)** 로 정리한다. 핵심은 **기존 평균/AND 결과가 한 톨도 안 바뀌는 것**:
- framePass(f): 평균 = (A+B)/2 ≥ 기준 · AND = min(A,B) ≥ 기준 · **차등 = A ≥ 기준A 그리고 B ≥ 기준B** (신규)
- 촬영 통과 = 모든 장 framePass (기존 "전 장 통과" 규칙 유지)
- 평균/AND의 공식은 그대로 옮겨오므로 **동일 입력 → 동일 판정**(회귀 없음). 신규 로직은 차등 모드에서만 실행.
- 이력 재판정: 장별 A/B 원점수를 이미 보관 중 → 방식·기준 바꾸면 즉시 재계산(기존과 동일 동작).
- **영향받는 판정 표시 지점(전수, 전부 DemoClient.tsx 내부)**: 최근결과 판정/색(373,374,364), 장별 표 색(414), 이력 판정/색(531), effLabel(206). 모두 boolean 기반으로 교체.
- **구현 후 반드시 테스트할 기존 기능**:
  1. 평균 모드 — 예전과 똑같은 판정/점수 (회귀 확인)
  2. AND 모드 — 예전과 똑같은 판정 (기본값, 회귀 확인)
  3. 기준값·판정방식 바꿀 때 이력 즉시 재판정
  4. 연속 3장·밝기 안내·크기 미달·질감 표시 그대로

const [mode, setMode] = useState<"avg"|"and"|"perModel">("and"); // 기본 AND 유지
const [thA, setThA] = useState(0.60); // 모델 A 기준 (차등 모드 전용)
const [thB, setThB] = useState(0.85); // 모델 B 기준

const framePass = (f) =>
  mode === "perModel" ? (f.v1se >= thA && f.v2 >= thB)
  : mode === "and"    ? (Math.min(f.v1se, f.v2) >= threshold)
  :                     ((f.v1se + f.v2) / 2 >= threshold);
const capturePass = (frames) => frames.length > 0 && frames.every(framePass);
