# [운영 주의] TRUST_PROXY=1을 켜기 전에 반드시 읽을 것

- 작성: 2026-08-03 (총괄 PM) · 배경: 종합검수 H-1(접속 IP 위조 차단, 커밋 `7f29160`)
- 읽는 사람: 운영 서버(프록시/nginx)를 구성하는 사람

## 현재 동작 (기본값)

- 서버는 클라이언트가 보낸 `X-Forwarded-For`(XFF) 헤더를 **믿지 않습니다.**
  IP는 위조 가능한 값이라 기본을 "안 믿음"으로 바꿨습니다(H-1).
- 그래서 지금은 **사무실 IP 판정이 "확인 불가", 접속기록 IP 칸이 빈칸**으로 나옵니다. **정상입니다.**

## 프록시를 세운 뒤 복구하는 법

1. nginx 등 리버스 프록시를 서버 앞에 세운다.
2. `.env`에 `TRUST_PROXY=1`을 넣는다.
3. ⚠️ **가장 중요**: nginx가 XFF를 **덮어쓰도록** 설정해야 한다.

```nginx
# ❌ 위험 — nginx 기본 관용구. 클라이언트가 보낸 XFF 값 "뒤에 덧붙이므로"
#    맨 앞이 위조값이 된다. 이대로 TRUST_PROXY=1을 켜면 IP 위조(H-1)가 되살아난다.
proxy_set_header X-Forwarded-For $proxy_add_x_forwarded_for;

# ✅ 안전 — 프록시가 직접 본 접속 IP로 "덮어쓴다".
proxy_set_header X-Forwarded-For $remote_addr;
```

## 왜 위험한가 (한 줄 설명)

`$proxy_add_x_forwarded_for`는 "클라이언트가 보낸 XFF + 실제 IP"를 이어 붙입니다.
코드가 XFF의 **맨 앞** 값을 읽으면, 공격자가 헤더에 사무실 IP를 적어 보내는 것만으로
"사무실에서 접속"으로 위장할 수 있습니다.

## 남은 개선 과제 (코드 쪽, 미착수)

- XFF 파싱을 "맨 앞"이 아니라 **"뒤에서 N번째(신뢰 프록시 수만큼)"** 방식으로 바꾸면
  nginx 설정 실수까지 방어된다. 운영 서버 구성(plan.md C. 5-B)을 정할 때 함께 처리 권장.
