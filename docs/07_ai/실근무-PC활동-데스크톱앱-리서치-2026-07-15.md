## 0. 왜 카메라가 아니라 PC 활동인가 (결정 요약)

- 카메라 상시(옵션 B)는 직원 거부감·국가인권위 "상시 감시" 리스크로 사무직에 부적합.
- PC 활동 방식 = PC 켜짐 + 키보드·마우스 **입력 유무(내용 아님)**로 재석/이석 판단. 시프티 데스크탑(PC-OFF)과 같은 검증된 방식.
- **개인 PC 문제**: 회사 지급 PC는 앱 설치 정당, 개인 PC·거부자는 강제 불가 → **선택형 + 대체수단**(출퇴근 기록 기반)으로 해결. 얼굴인증과 같은 원칙.

## 1. 기술 구현 (요약)

### 프레임워크 비교
| 항목 | Electron | Tauri | 네이티브 C#/.NET |
|---|---|---|---|
| 방식 | 크롬 통째 포함 | 윈도우 내장 웹뷰 사용 | Windows 전용 새로 작성 |
| 설치파일 | 80~150MB | 3~10MB | 수 MB(최경량) |
| 메모리 | 150~300MB | 30~50MB | 최소 |
| 상시 백그라운드 | 무겁지만 검증됨 | 가벼워 유리 | 가장 유리 |
| 웹자산 재활용 | 쉬움 | 되나 Rust 학습 | 거의 안 됨 |

- **우리 결론**: 화면 거의 없고 상시 백그라운드로 도는 앱 → **Tauri(웹자산 재활용 시) 또는 네이티브 C#(최경량)** 권장. Electron 비추천. 최종은 프로토타입 단계에서 확정.

### 유휴(idle) 감지 — 핵심
- Windows 표준 API `GetLastInputInfo`로 **"마지막 입력 시각"만** 읽음 → 지금 시각과 빼서 "몇 초째 조용한가" 계산.
- **입력 내용은 구조적으로 알 수 없음 → 키로깅 아님.** 우리 요구("활동 유무만")에 정확히 부합.
- 잠금(Lock)·절전·원격(RDP) 상태는 세션 이벤트로 함께 받아 이석 판정 보정.
- **웹(브라우저)만으로는 불가**: 브라우저 유휴감지 API는 ①크롬 전용 ②탭 열림 중에만 ③60초 단위 ④권한팝업 필요 → 상시·정확 측정 불가. **이것이 별도 데스크톱 앱을 만드는 근본 이유.**

### 배포·서명
- 코드 서명(디지털 인감) 필요 — 없으면 설치 시 Windows 경고(SmartScreen).
- 비용: OV 약 200~300불/년, EV 250~500불/년+토큰, **Microsoft Trusted Signing 월 약 9.99불(최신·저렴 권장)**.
- 2024.3 정책변경으로 EV도 즉시 경고면제 아님(평판 축적 필요). 자동 업데이트 파일도 매번 서명.

### 웹앱 연동
- 딥링크(`앱://`) + 보안토큰(Authorization Code + PKCE) 방식: 웹 로그인 → "앱 연결" 버튼 → 일회용 코드 → 앱이 자기 토큰 발급받아 저장 → 이후 회사ID·직원ID 매핑.
- 이석/재석 이벤트를 `{직원ID, 상태, 시각}`으로 서버 API 전송(오프라인 시 로컬 버퍼링 후 재전송). **서버는 수신 엔드포인트만 추가하면 됨**(근태 화면 기존재).

### 개인정보·신뢰 설계
- 키내용·화면캡처 코드 자체를 넣지 않음 → "할 기능이 없는" 설계. 서버 전송 스키마도 상태·시각만.
- 트레이 아이콘 상시 표시 + "보는 것/안 보는 것" 목록 고지 + 설치 시 동의 + 직원 본인 데이터 열람.

## 2. 특허·선행기술 스캔

> ⚠️ 변리사 아님 · 법적 판단(FTO) 아님 · 참고용 스캔.

- **개념 층위 리스크 낮음**: "무입력=이석", "PC 사용시간 근태", "PC-OFF"는 2000년대 초부터의 확립된 선행기술. 국내외 다수 업체(시프티·에스원·오피스키퍼·Hubstaff 등) 공통 제공 → 특정 1사 독점 불가. 미국은 Alice 판례로 유사 SW특허 대거 무효.
- 국내 공개검색상 넓은 개념 독점 특허 미확인(KT 근태특허는 소멸·무관). 국내 특허는 "특정 구현형"이 주류 → 구성요소 그대로 복제만 안 하면 침해 성립 어려움.
- **안전 가이드**: 보편 개념은 자유롭게, 특정 제품 UI/알고리즘 복제 금지, 독립개발 문서화. **상용출시·투자유치·경고장 수령 임박 시 변리사 KIPRIS 전수조사+FTO 의뢰.**
- **현재 판단: 리스크 낮음(개념 기준), 최종은 변리사 확인.**

## 3. 경쟁사 벤치마크 → 반드시 넣을 3종

1. **설정형 무입력 임계값** (고정값 쓰는 제품 없음): 기본 사무직 10분 / 콜센터 5분 / 관리자 20분 프리셋. (참고: DeskTime 3분, Hubstaff 20분, Time Doctor 3~30분 설정)
2. **소명 루프**: 유휴 감지 시 "일하고 계셨나요?" 확인 + 사후 소명(전자결재). 없으면 회의·전화 많은 직군에서 반드시 분쟁.
3. **회의앱 화이트리스트**: Zoom·Teams·구글미트 실행 중이면 입력 없어도 근무 인정 → "정직한 실근무시간" 차별점의 핵심.
- 그 외: **스크린샷 없는 activity-only**(키/마우스 눌림 여부+유휴만), Windows·macOS 지원, 클라우드 배포·PC대수 과금이 국내 표준. 우리는 "투명한 기준 공개"를 역으로 마케팅 포인트化 가능.

### 시프티 데스크탑 동작(요약)
- 일정시간 무입력 → 이석 간주 + PC 사용 제한(PC-OFF), 그 시간 빼고 실근로 집계. 소명은 즉시 or 사후, 전자결재 처리. Windows·macOS, 클라우드. **구체 임계값·요금 비공개(도입문의).**

## 4. 단계별 개발 계획 (보류 중 — 재개 시 이 순서)

| 단계 | 내용 | 비용/리스크 |
|---|---|---|
| **1단계(권장 시작점)** | 동작 확인용 미니 프로토타입 — 테스트 PC에서 유휴/이석/재석 실제 감지 확인. 웹연동·서명·배포 없음 | ~0, 1~2일 |
| 2단계 | MVP 앱 — 웹 로그인 연동 + 이석/재석 서버 전송 + 실근무 반영 + 소명 루프 + 설정형 임계값 + 동의화면 | 중 |
| 3단계 | 배포화 — 코드서명·자동업데이트·설치본·회의앱 화이트리스트, (원하면) Mac | 중~높(서명 비용) |
