## 1. PC-OFF가 뭔가 (쉬운 정의)

- **PC오프제 = 정해진 퇴근시간이 되면 직원 PC 사용을 자동으로 막아서(잠금/종료) 퇴근을 유도하는 제도.**
- 반대로 출근 전·휴무일에도 PC를 못 쓰게 막는다. 즉 **"근무일정에 등록된 시간에만 PC가 켜진다"**.
- 배경: 주52시간제(법정 근로시간 상한) 시행 이후, "기록상 퇴근했는데 실제로는 야근"하는 공짜야근을 막고 근로시간을 정확히 관리하려고 대기업·은행권부터 확산됨.
- 우리가 7/15에 확정한 "PC 활동 기반 실근무 측정"(이석 감지)과 **같은 데스크톱 앱 계열 기능**이다. 차이는:
  - **측정(우리가 이미 결정한 것)**: PC 입력 유무를 보고 실근무시간을 계산 — "지켜보기"
  - **제어(PC-OFF)**: 근무시간 밖에는 PC를 잠가버림 — "막기"

## 2. 대표 제품 동작 방식 (벤치마크)

### 시프티 데스크탑 (PC-OFF)
- 근무일정에 따라 PC 사용을 제어. 승인된 근로시간 외에는 이용 제한, 휴무일 사용 불가.
- 일정 시간 무입력 → 이석 판단 → 휴게시간 정산(실근로에서 제외).
- 웹·앱·PC 실시간 동기화, 단축/연장근무 신청 지원. 요금·임계값은 비공개(도입문의).

### 에스원 PC OFF 4.0
- 근무표 기준 **차단 전 사전 알림창** → 차단창 팝업 → PC 차단/종료. (저장 안 된 문서 날리는 사고 예방용 사전 알림)
- **연장근무 신청 → 부서장 대시보드에서 결재** → 승인된 시간만큼 PC 사용 연장.
- 부서/사용자별 **초과근로 한도(주/월) 관리** — 법정 한도 초과 임박 시 본인·관리자 자동 통보.
- 개인·그룹·부서별 예외 설정(한도·휴게시간·일시사용 시간), 모바일 출퇴근·근태기기 데이터 통합.

### 공통 기능 구성(= PC-OFF 제품의 표준 부품 5가지)
1. **예약 차단**: 근무일정 밖 시간에 PC 잠금(차단창) 또는 종료
2. **사전 알림**: 차단 N분 전 경고(문서 저장 유도)
3. **연장근무 신청·결재 연동**: 야근 필요 시 신청 → 승인되면 그 시간만 PC 열어줌
4. **일시사용(비상) 허용**: 짧은 시간 임시 해제(사유 기록)
5. **주52시간 한도 경보**: 누적 근로시간이 한도에 다가가면 본인·관리자에게 알림

## 3. 우리 제품에 어떻게 적용하나

### 핵심 결론: "새 제품"이 아니라, 이미 계획한 데스크톱 앱에 얹는 **추가 모듈**이다
7/15 리서치에서 확정한 PC 활동 측정 앱(Tauri 또는 C#, 현재 보류)이 그대로 토대가 된다. 측정 앱이 이미 갖출 것(상시 실행, 웹앱 로그인 연동, 서버 통신, 트레이 아이콘)에 **"잠금 화면 띄우기 + 일정 확인"만 더하면** PC-OFF가 된다.

### 우리가 이미 가진 것과의 연결 (재사용 지도)
| PC-OFF에 필요한 것 | 우리 웹앱 현황 | 재사용 방법 |
|---|---|---|
| 근무일정(언제 잠글지 기준) | 근무시간 설정 기존재 | 데스크톱 앱이 서버에서 일정 조회 |
| 연장근무 신청·결재 | **초과근무 신청+결재선+결재함 이미 완성** | 승인되면 그 날짜·시간만 잠금 해제 — 화면 새로 만들 필요 없음 |
| 밀린 결재로 못 여는 문제 | **밀린 결재 현황판+대리처리 완성(7/24)** | "퇴근 직전 신청했는데 결재자 부재" 상황의 안전판 |
| 이석/실근무 집계 | 데스크톱 앱 리서치 완료(보류) | 측정과 제어를 한 앱에서 |
| 주52시간 경보 | 근태 데이터 기존재 | 서버에서 주간 누적 계산 → 알림(추후) |

### 구현 방식 권장(중요한 설계 선택)
- **강제 전원종료(shutdown)가 아니라 "전체화면 잠금(차단창)" 방식 권장.**
  - 이유: ①저장 안 된 문서 손실 사고 방지 ②백신·백업 등 야간 작업 방해 없음 ③"비상 해제" 버튼을 잠금화면에 둘 수 있음. 에스원도 차단창 팝업이 기본이고 종료는 옵션.
- 잠금화면에 넣을 것: 남은 연장승인 시간 / **[연장근무 신청]** 버튼(웹앱 초과근무 신청으로 연결) / **[일시사용]**(사유 입력, 관리자에게 기록 통보).
- **선택형 원칙 유지**: 얼굴인증과 동일하게 회사별로 켜고 끄는 옵션. 개인 PC·거부자 강제 불가.

### 단계 제안 (데스크톱 앱 계획에 통합)
| 단계 | 내용 |
|---|---|
| 1단계 | (기존 계획 그대로) 유휴 감지 프로토타입 — 여기에 **"지정 시각에 전체화면 잠금" 실험 1개만 추가** (~1일 추가) |
| 2단계 | MVP: 근무일정 연동 잠금 + 사전 알림(10분/5분 전) + 승인된 초과근무만 해제 + 일시사용 |
| 3단계 | 주52시간 누적 경보, 부서별 예외 설정, 관리자 대시보드 |

## 4. 주의점 (도입 전에 알아야 할 함정)

1. **"공짜야근 제조기" 역효과가 가장 큰 리스크.** 부서장이 연장 결재를 안 해주면 PC는 꺼졌는데 일은 남아서, 개인 노트북·서브 PC로 몰래 일하는 사례가 언론에 여러 번 보도됨(국민일보·잡플래닛). → 우리 해법: **연장 신청을 쉽게(잠금화면에서 바로) + 밀린 결재 현황판으로 결재 지연 차단.** "차단"보다 "기록"이 목적임을 제품 메시지로.
2. **PC-OFF 이후에 일한 시간도 근로시간이다.** 잠갔다고 근로가 아닌 게 아님 — 실제로 일했으면 수당 대상. 우회 근무 흔적(모바일 접속 등)이 있으면 오히려 회사에 불리한 증거가 됨. 도입 기업에 이 점을 안내하는 가이드 필요(노무사 검토 1회 권장).
3. **강제 종료로 인한 데이터 손실 민원** — 사전 알림 + 잠금(비종료) 방식으로 원천 회피.
4. **우회 수단(공용PC·개인기기)은 기술로 다 못 막는다** — 조직문화 문제라는 한계를 영업 시 솔직히 안내(과대 약속 금지).
5. 특허: 7/15 스캔 결과 PC-OFF는 2000년대부터의 확립된 선행기술로 개념 리스크 낮음(상용 출시 전 변리사 확인은 동일하게 필요).

## 5. 경쟁 관점 요약

- 시프티·에스원 모두 PC-OFF를 **부가서비스(별도 과금)**로 판매 → 우리도 기본 요금에 끼워주면 차별점, 별도 과금하면 수익원. 중소기업 대상이므로 **"설정 3분, 결재는 기존 결재함 그대로"** 같은 단순함이 승부처.
- 우리 고유 조합: **얼굴인증 출퇴근(본인확인) + PC 활동 실근무(정직한 시간) + PC-OFF(법규 준수)** — 3종 세트를 한 데스크톱 앱·한 웹앱에서.
