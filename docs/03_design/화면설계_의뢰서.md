# 화면설계 의뢰서 — 근태관리 웹 SaaS

> 이 문서는 외부 AI 디자인 도구("클로드 디자인" 등)에 그대로 전달해 화면을 만들 때 쓰는 의뢰서입니다.
> 이 문서 하나만 읽어도 화면을 만들 수 있도록, 필요한 내용을 모두 담았습니다.
> 작성일: 2026-07-04

---

## 1. 프로젝트 소개

**무엇을 만드는 서비스인가**
중소기업 사무직을 위한 **웹 기반 근태관리 서비스(구독형 SaaS)**입니다. 직원은 출근/퇴근을 얼굴인증 또는 GPS(위치) 중 편한 방법으로 기록하고, 관리자는 직원들의 실제 근무시간과 법정 근로기록을 한눈에 확인합니다.

**핵심 가치**
- 정직한 실근무시간: 자리비움 시간을 반영한 실제 근무시간 산출
- 법규 자동 준수: 5인 이상 사업장 근로시간 기록 3년 보존
- 강제하지 않는 얼굴인증: 얼굴인증은 선택이며, GPS 등 대체 수단을 항상 함께 제공

**사용자는 두 종류입니다**
| 사용자 | 주 사용 기기 | 주요 화면 |
|---|---|---|
| **관리자** (인사 담당자/대표) | **PC 웹** 중심 | 대시보드, 직원 관리, 근태 현황, 리포트 |
| **직원** (사무직 근로자) | **모바일 웹** 중심 | 출퇴근 화면, 얼굴/GPS 인증, 내 근태 조회 |

## 2. 디자인 컨셉 (기업용 SaaS 톤)

**한 줄 컨셉**: "중소기업이 매일 업무로 쓰는, 신뢰감 있고 군더더기 없는 근태관리 도구"

**참고할 서비스(무드 레퍼런스)**
- **Linear, Notion, Vanta** — 깔끔한 여백, 절제된 색 사용, 정보 위계가 명확한 기업용 SaaS 톤
- **국내 근태관리 서비스(시프티, 플렉스류)의 대시보드** — 카드형 현황 요약 + 표 중심의 데이터 가독성

**무드 키워드 (5~7개)**
1. 신뢰감 있는 (Trustworthy)
2. 정갈한 (Clean)
3. 데이터 가독성 높은 (Data-legible)
4. 절제된 (Restrained) — 과한 장식·그라데이션 배제
5. 넉넉한 여백 (Breathable)
6. 표·카드 중심 (Table & Card-driven)
7. 업무용 (Professional, not playful)

**영역별 톤 차이**
- **관리자 화면(PC)**: 정보 밀도를 조금 높여도 됨. 표·필터·카드가 한 화면에 여러 개 있어도 괜찮음.
- **직원 화면(모바일)**: 최대한 단순하게. 버튼은 크고(터치하기 쉽게), 화면당 할 일은 1가지로 제한.

**하지 말 것**
- 화려한 그라데이션, 과도한 그림자, 장식적 일러스트
- 색상 남용 (아래 토큰 표에 없는 색 임의 추가 금지)
- 재미있는/캐주얼한 톤 (이모지 남용, 유머러스한 문구 등)

## 2-5. 실제 참고 서비스 (구체 예시)

아래 두 서비스를 무드 레퍼런스로 삼되, **기능을 그대로 베끼지 말고 "느낌"만 참고**한다. (우리 기능 범위는 5장 참조)

| 무엇을 참고 | 참고 서비스 | 포인트 |
|---|---|---|
| **관리자 화면(PC)** 전문적 룩 | **시프티(shiftee.io)** | 흰 배경 + 진한 파랑/네이비, **카드형 현황 요약 + 표 중심**, 넉넉한 여백, 과한 장식 없음 |
| **직원 모바일 얼굴/GPS 인증 UX** | **지블(jibble.io)** | **셀카(얼굴) 인증** 화면, **지도 위 GPS 위치 표시**, 큰 버튼·단순 1컬럼 |
| **랜딩에서 차별점 보여주기** | 지블의 "부정행위 방지" 섹션 방식 | 우리는 이 방식으로 **"정직한 실근무시간 · 법규 자동 준수 · 강제 안 하는 얼굴인증"** 을 섹션으로 강조 |
| 공통 톤 | 시프티·지블 공통 | 파랑+흰+회색, 기능별 **실제 스크린샷** 제시, 신뢰 요소(고객 로고·보안 배지) |

> ⚠️ 지블은 "얼굴인증을 매 출퇴근마다 **필수**"로 만들지만, 우리는 **선택형(강제 금지)** 이다(6장 특수 요소 ①). 이 점만은 지블을 따라하지 말 것.

## 3. 디자인 토큰 요약

> 아래 값은 "출발점"이며 확정된 브랜드 컬러가 아닙니다. 그러나 이 문서 기준으로 화면을 만들어 주세요. Primary 색만 나중에 교체해도 전체가 일관되게 바뀌는 구조를 권장합니다.

### 3-1. 색상

| 용도 | 값 | 어디에 쓰나 |
|---|---|---|
| Primary (주 브랜드색) | `#2563EB` (파랑) | 주요 버튼("출근하기", "가입하기"), 강조 링크 |
| Success (성공/정상) | `#16A34A` (초록) | 출근 완료, 동의 완료, "정상" 상태 |
| Warning (주의) | `#F59E0B` (주황) | 지각, 자리비움, "확인 필요" 배지 |
| Danger (위험/삭제) | `#DC2626` (빨강) | 얼굴 데이터 삭제, 퇴사 처리 등 되돌릴 수 없는 동작 |
| 본문 텍스트 | `#111827` (Neutral-900) | 일반 본문 글자 |
| 보조 텍스트 | `#6B7280` (Neutral-500) | 안내 문구, 캡션, 날짜 |
| 테두리/구분선 | `#E5E7EB` (Neutral-200) | 카드 테두리, 표 구분선 |
| 배경 | `#F9FAFB` (Neutral-50) | 페이지 배경 |
| 표면(카드 등) | `#FFFFFF` (White) | 카드, 입력창, 팝업 배경 |

- 명도대비: 본문 텍스트와 배경은 최소 **4.5:1** 이상 확보.
- 경고/위험 색은 **색만으로 표시하지 말고 아이콘+텍스트를 함께** 사용 (예: "⚠️ 지각").

### 3-2. 글꼴 및 크기

| 용도 | 값 |
|---|---|
| 기본 글꼴 | Pretendard (한글), 시스템 기본 sans-serif |
| Display (핵심 숫자 강조) | 28px — 예: "실근무시간 8시간 48분" |
| Heading (화면 제목) | 20px — 예: "직원 관리", "내 근태 조회" |
| Body (본문 기본) | 16px |
| Caption (보조 설명) | 13px |

- 글자 굵기는 기본(Regular)/강조(Bold-SemiBold) 2단계만 사용.

### 3-3. 간격 (4px 배수)

| 토큰 | 값 | 용도 |
|---|---|---|
| spacing-xs | 4px | 아이콘-텍스트 사이 좁은 간격 |
| spacing-sm | 8px | 버튼/입력창 내부 여백 |
| spacing-md | 16px | 카드 내부 여백, 항목 간 기본 간격 |
| spacing-lg | 24px | 섹션과 섹션 사이 |
| spacing-xl | 32px | 화면 상/하단 여백 |

### 3-4. 버튼 / 입력 규칙

| 버튼 상태 | 배경색 | 텍스트색 |
|---|---|---|
| 기본 | Primary `#2563EB` | White |
| 눌림 | Primary보다 약간 어둡게 | White |
| 비활성화 | `#E5E7EB` | `#6B7280` |
| 위험 동작 | Danger `#DC2626` | White |

- 모서리 반경: 버튼/카드 8px, 입력창 4px, 팝업 12px, 원형 아이콘/상태점 완전 원형
- 버튼·입력창 최소 크기: **가로/세로 44px 이상** (터치 오조작 방지)

### 3-5. 접근성 (반드시 지킬 것)

| 항목 | 기준 |
|---|---|
| 터치 영역 | 버튼·입력창 최소 44×44px |
| 명도대비 | 본문 텍스트 대 배경 최소 4.5:1 |
| 색 단독 사용 금지 | 경고/위험 정보는 색+아이콘/텍스트 병행 |
| 로딩 상태 안내 | 카메라 촬영·위치 확인 중에는 "확인 중..." 같은 텍스트도 함께 표시 |

## 4. 공통 규칙

- **반응형**: 관리자 화면은 PC 웹(넓은 화면) 기준으로 설계하되 태블릿에서도 깨지지 않게. 직원 화면은 모바일 웹(좁은 화면) 기준으로 설계하되 PC에서 봐도 어색하지 않게.
- **관리자 레이아웃**: 상단바 또는 좌측 네비게이션 + 본문 영역 구조. 메뉴 항목: 대시보드 / 직원관리 / 근태현황 / 리포트 / 생체정보 / 설정.
- **직원 레이아웃**: 상단에 간단한 타이틀바(뒤로가기 또는 메뉴), 본문은 세로 스크롤 1컬럼.
- **빈 화면 상태**: 데이터가 없을 때 "아직 기록이 없습니다" 같은 안내 문구를 중앙에 표시 (빈 화면도 하나의 화면으로 제작).
- **에러 상태**: 404/500 등 오류 시 에러 메시지 + "홈으로 이동" 버튼.
- **로딩 상태**: 카메라·위치 확인 등은 스피너 + 안내 텍스트("확인 중...")를 함께 표시.
- **언어**: 모든 화면은 한국어 UI.

### 5-1. 공개/온보딩 영역

#### ① 회사 회원가입 ⭐
- **사용자**: 공개(비로그인)
- **목적**: 회사(관리자) 계정을 처음 만든다
- **필수 요소**: 회사명 입력 / 이메일 입력 / 비밀번호 입력 / "가입하기" 버튼 / 로그인 화면으로 이동 링크
- **샘플 콘텐츠**: 회사명 "㈜하늘테크", 이메일 "admin@skytech.co.kr"
- **참고 뼈대**: wireframes.md 4-2 (타이틀+입력필드 나열+제출버튼 폼 패턴)

#### ② 로그인 ⭐
- **사용자**: 공개(관리자/직원 공용)
- **목적**: 기존 계정으로 접속. 로그인 후 역할(관리자/직원)에 따라 자동으로 다른 화면으로 이동
- **필수 요소**: 이메일 입력 / 비밀번호 입력 / "로그인" 버튼 / "비밀번호를 잊으셨나요?" 링크
- **샘플 콘텐츠**: 이메일 "hong@skytech.co.kr"
- **참고 뼈대**: wireframes.md 4-3 (회원가입과 동일 폼 패턴 재사용)

#### ③ 회사 초기설정(온보딩)
- **사용자**: 관리자 (회원가입 직후 1회)
- **목적**: 서비스 사용에 꼭 필요한 기본 정보를 3단계로 입력
- **필수 요소**: 3단계 마법사(Wizard) 형태, 상단 진행 바(●─○─○). 1단계: 표준 근무시간(예: 09:00~18:00). 2단계: 사업장 주소 검색 + 지도 미리보기 + 허용 반경(m) 입력. 3단계: 5인 이상 사업장 여부(예/아니오) 라디오 선택. 각 단계 "이전/다음" 버튼, 마지막은 "설정 완료" 버튼
- **샘플 콘텐츠**: 반경 "100m", 5인 이상 "예"
- **참고 뼈대**: wireframes.md 3-1

#### ④ 랜딩 페이지
- **사용자**: 공개
- **목적**: 서비스 소개, 가입 유도
- **필수 요소**: 헤더(로고, 로그인/무료로 시작하기 버튼) / 핵심 가치 문구("정직한 실근무시간, 강제하지 않는 얼굴인증") / 차별점 요약 카드 3개(정직한 실근무시간 / 법규 자동 준수 / 강제 없는 얼굴인증)
- **참고 뼈대**: wireframes.md 4-1 (요약 수준만)

### 5-2. 관리자 영역 (PC 웹 중심)

#### ⑤ 관리자 대시보드 ⭐
- **사용자**: 관리자
- **목적**: 오늘의 근태 현황을 로그인 직후 한눈에 파악
- **필수 요소**: 상단 메뉴(대시보드/직원관리/근태현황/리포트/생체정보/설정) / 오늘 날짜 표시 / 카드형 요약 4개("출근 N명", "미출근 N명", "지각 N명", "실근무 평균 시간") — 미출근·지각 카드는 클릭 가능(경고 표시) / "주의가 필요한 직원" 목록(예: "김OO - 지각(09:20 출근)")
- **샘플 콘텐츠**: 출근 18명 / 미출근 2명 / 지각 1명 / 실근무 평균 8.4시간
- **참고 뼈대**: wireframes.md 3-2

#### ⑥ 직원 목록/관리 ⭐
- **사용자**: 관리자
- **목적**: 직원을 등록·초대·조회, 상태 확인
- **필수 요소**: 상단 "+ 직원 초대" 버튼 / 목록 표(이름, 부서, 상태[재직중/초대중/퇴사], 인증방식[얼굴인증/GPS], 생체동의 여부, "상세>" 버튼)
- **샘플 콘텐츠**: "홍길동 · 영업팀 · 재직중 · 얼굴인증 · 동의함", "김OO · 총무팀 · 초대중"
- **참고 뼈대**: wireframes.md 3-3

#### ⑦ 직원 초대(등록) ⭐
- **사용자**: 관리자
- **목적**: 신규 직원에게 초대를 보낸다
- **필수 요소**: 이메일 입력(단건 또는 여러 명 추가 가능) / "초대 발송" 버튼. (팝업 또는 사이드 패널 형태 권장)
- **샘플 콘텐츠**: "kim@skytech.co.kr"

#### ⑧ 직원 상세/수정
- **사용자**: 관리자
- **목적**: 개별 직원 정보 확인·수정
- **필수 요소**: 기본 정보(이름/부서/직급) / 인증방식 현황(얼굴인증 사용 중 등) / 생체정보 동의 상태 및 동의일 / "정보 수정" 버튼 / "퇴사 처리" 버튼(위험 동작 스타일)
- **샘플 콘텐츠**: "홍길동 · 영업팀 · 대리 · 얼굴인증 사용 중 · 생체정보 동의: 동의함(2026-06-01)"
- **참고 뼈대**: wireframes.md 3-3-1

#### ⑨ 근무제·기준시간 설정
- **사용자**: 관리자
- **목적**: 회사의 근무시간 기준을 설정
- **필수 요소**: 표준 근무시간 입력 / 사업장 위치·GPS 허용 반경 설정 / 실근무시간 산출 주기 설정(옵션 B 관련, "몇 분마다 확인" 설정값)

#### ⑩ 근태 현황 조회(전체)
- **사용자**: 관리자
- **목적**: 기간별/부서별 출퇴근 현황 조회
- **필수 요소**: 필터 영역(기간 시작~종료, 부서 선택, "조회" 버튼) / 목록 표(이름, 날짜, 출근시각, 퇴근시각, 실근무시간). 행 클릭 시 직원별 상세로 이동
- **샘플 콘텐츠**: "홍길동 · 07/04 · 09:02 · 18:05 · 8:48", "김OO · 07/04 · 09:20 · - · (근무중)"
- **참고 뼈대**: wireframes.md 3-4

#### ⑪ 직원별 근태 상세
- **사용자**: 관리자
- **목적**: 특정 직원의 날짜별 출퇴근 기록 확인
- **필수 요소**: 상단 기본 정보 + 날짜별 출퇴근시각·자리비움 시간·실근무시간 목록 (직원 상세와 동일한 "상세형" 뼈대 재사용)

#### ⑫ 실근무시간 리포트
- **사용자**: 관리자
- **목적**: 실근무시간 집계 확인 (1차는 표만, 그래프는 추후 제공)
- **필수 요소**: 단위 전환 탭(일/주/월) + 기간 필터 / 표(이름, 실근무시간, 자리비움시간, 비고) / 하단에 "그래프·통계는 추후 제공 예정" 안내 문구
- **샘플 콘텐츠**: "홍길동 · 42:30 · 1:20", "김OO · 40:00 · 0:45"
- **참고 뼈대**: wireframes.md 3-5

#### ⑬ 법정 근로기록 조회
- **사용자**: 관리자
- **목적**: 법정 증빙자료 확인 (1차는 조회만, 내보내기는 추후 제공)
- **필수 요소**: 기간 필터(최대 3년 범위) / 표(이름, 날짜, 출근, 퇴근, 근무시간) / 하단에 "CSV/PDF 내보내기는 추후 제공 예정" 안내 문구
- **참고 뼈대**: wireframes.md 3-7

#### ⑭ 생체정보 동의·파기 관리

- **목적**: 직원별 생체정보 동의 현황·파기 이력 확인 (법적 필수 화면)
- **필수 요소**: 목록 표(이름, 동의상태[동의함/철회함], 동의일, 파기이력) / "파기 이력 전체 로그 보기" 버튼

## 6. 특수 UI 요소 (법적으로 중요 — 반드시 반영)

이 서비스는 "얼굴 = 생체정보"를 다루기 때문에 아래 요소들은 임의로 생략하거나 축소하면 안 됩니다.

| # | 요소 | 내용 | 들어가는 화면 |
|---|---|---|---|
| ① | 얼굴인증 "강제 아님" 고지 + 선택 카드 | "둘 중 하나를 반드시 골라야 하는 건 아니며, 나중에 바꿀 수 있습니다"를 화면 진입 즉시 보이게. 얼굴인증/GPS 두 카드를 동등한 크기·비중으로 제시(한쪽을 더 강조하지 않음) | ⑯ 인증방식 선택 안내 |
| ② | 생체정보 별도 동의 화면 | 체크박스를 체크하기 전에는 "동의하고 계속하기" 버튼이 비활성화(회색) 상태여야 함. 수집 항목·목적·보관기간·철회 방법을 각각 별도 박스로 분리 표시 | ⑰ 생체정보 동의 화면 |
| ③ | 옵션 B 안내 배너 | "몇 분마다 자리확인용으로 카메라가 짧게 작동합니다. 사진은 저장되지 않습니다"를 근무 시작 후 최초 1회 눈에 띄게 고지. 이후엔 작고 소극적인 상태 표시로 전환(감시받는 느낌 최소화) | ㉓ 근무 중 자리확인 안내 |

| ⑤ | GPS 위치확인/반경 안내 | 위치 확인 중 로딩 표시, 반경 이내/밖 결과를 명확히 구분해 표시(반경 밖일 땐 이유와 "다시 시도" 안내) | ㉒ GPS 확인(출퇴근) |

추가로 ㉖ "내 정보/얼굴 재등록·삭제" 화면의 "동의 철회(삭제)" 버튼도 눈에 잘 띄는 위치에 두되, 실수로 누르지 않도록 확인 팝업을 반드시 거치게 해주세요.

## 7. 클로드 디자인에 요청하는 팁

이 문서를 클로드 디자인(또는 유사 AI 디자인 도구)에 전달할 때 아래 순서로 진행하는 것을 권장합니다.

1. **한 번에 다 요청하지 말고 영역 단위로 나눠서 요청하세요.**
   - 예: "먼저 3장 디자인 토큰을 적용한 기본 스타일 가이드부터 만들어줘" → 다음 "회원가입/로그인 화면 만들어줘" → 다음 "관리자 대시보드 만들어줘" 순서로.
2. **토큰(3장)을 가장 먼저 알려주고 시작하세요.** 색상·글꼴·간격을 먼저 등록해두면 이후 화면들이 서로 다르게 나오는 것을 막을 수 있습니다.
3. **핵심 흐름 6개(5장 ⭐ 표시)부터 만들어달라고 요청하세요.** 이 6개가 되면 서비스의 기본 골격을 확인할 수 있습니다.
4. **관리자 화면과 직원 화면을 섞어서 요청하지 마세요.** "PC용 관리자 화면 먼저 전부" 또는 "모바일용 직원 화면 먼저 전부" 식으로 기기별로 묶어 요청하면 톤이 일관됩니다.
5. **6장의 특수 UI 요소는 화면을 만들 때마다 다시 한번 강조해서 요청하세요.** (예: "이 화면엔 동의 전 버튼 비활성화를 꼭 반영해줘") AI가 일반 SaaS 패턴으로 단순화해버리기 쉬운 부분입니다.
6. **완성된 화면은 이 문서의 "필수 요소" 목록과 대조해서 빠진 게 없는지 확인하세요.**
