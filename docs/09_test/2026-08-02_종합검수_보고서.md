## 0. 한 장 요약 (사장님용)

지금 이 프로그램은 **화면과 기능은 잘 만들어져 있으나, 사람이 실수하거나 여러 명이 동시에 쓸 때 숫자가 어긋나는 급소가 몇 군데 있다.** 특히 다음 3가지는 실제 회사에 팔기 전에 반드시 고쳐야 한다.

1. **연차가 잔여보다 많이 나갈 수 있다.** 직원이 신청을 여러 번 넣으면 잔여 검사를 빠져나가고, 승인할 때는 잔여를 다시 확인하지 않는다. 연차가 마이너스가 된다. (급여·법정 기록과 직결)
2. **출근 버튼을 빨리 두 번 누르면 그 직원은 다시는 출근을 못 찍는다.** "퇴근 안 한 기록"이 하나 남아버려서, 이후 모든 출근이 조용히 무시된다. 화면엔 계속 "근무 중"으로 보인다.
3. **퇴근 버튼을 깜빡한 기록이 리포트·엑셀에서 수백 시간으로 부풀어 오른다.** 게다가 대시보드는 정상 숫자, 리포트는 부풀린 숫자를 보여줘 **같은 회사 같은 주인데 화면마다 근무시간이 다르다.** 이 엑셀이 노동청 제출용 증빙이다.

여기에 더해, **결제 테스트용으로 만든 화면 하나(`/kicc-test`)가 로그인 없이 아무나 우리 서버를 이용해 다른 주소를 대신 호출하게 열려 있다.** 외부 공격자가 우리 서버를 발판으로 사내 얼굴인식 서버를 두드릴 수 있는 상태다. 이건 기능 문제가 아니라 **보안 사고**이므로 가장 먼저 지워야 한다.

**총 발견**: 즉시 조치 6건 · 높음 7건 · 중간 22건 · 경미 18건 (중복 제거 후)

**잘 되어 있는 것도 분명히 있다** — SQL 인젝션 통로 0건, 회사 간 데이터 격리(다른 회사 데이터를 건드리는 쿼리 0건), 파일 업로드 검증, 관리자 페이지 22곳 전부 서버에서 차단, 마지막 관리자 보호, 미사용 코드 0건, 비밀키 하드코딩 0건. 기본기는 튼튼하다.

- **재현/실제**: 집에 있는 직원이 프록시·확장으로 `X-Forwarded-For: <회사 등록 IP>`를 붙여 출근 → `ipMatch` 통과 → `locationStatus = "verified"`. 코드는 신뢰 프록시 개념 없이 **가장 왼쪽(=클라이언트가 넣은 값)** 을 채택한다
- **영향**: 제품 차별점인 "정직한 실근무시간"의 위치확인이 헤더 한 줄로 무력화. 차단 IP 명단·이상접속 경보도 신뢰 불가
- **심각도**: High · **개선**: 신뢰 프록시 홉 수를 .env로 두고 오른쪽에서 n번째를 취하거나, 프록시가 없으면 XFF 무시. 최소한 사무실 IP 판정에는 XFF를 쓰지 말 것

### H-2. `/api/bizregcheck` — "검증 후 반드시 삭제"라고 적힌 임시 라우트가 무인증으로 살아 있음

- **위치**: `app/api/bizregcheck/route.ts:1`(파일 스스로 삭제 경고), `:14` 인증 없는 GET, `:30` `키설정됨: Boolean(process.env.BIZREG_API_KEY)`
- **실제**: 호출 1회당 국세청 API를 최대 8회(4건×2회 재시도), 최대 20초 소모. API 키 설정 여부까지 노출
- **영향**: 외부인이 반복 호출 → **국세청 일일 쿼터 고갈 → `verifyBizRegNo`가 `unknown` 반환 → 가입이 fail-open(통과)** 이라 가짜 사업자번호 가입이 전부 뚫린다. 요청당 20초 점유로 저비용 서비스 마비도 가능. `webapp/CLAUDE.md`의 자체 규칙 위반이며 아직 git 미커밋 상태
- **심각도**: High · **개선**: 폴더 삭제

### H-3. 운영을 개발 서버(`npm run dev`)로 실행 → 세션 쿠키 Secure 미적용 + 오류 내부정보 노출

- **위치**: `lib/session.ts:19` `secure: process.env.NODE_ENV === "production"` ↔ 실행 스크립트 `근태관리_실행.bat`(git 추적됨) 마지막 줄 `call npm run dev`
- **실제**: dev 모드는 `NODE_ENV=development` → **쿠키에 Secure 플래그가 안 붙는다.** HTTP로 한 번이라도 접근되면 세션 토큰이 평문 전송. 더불어 dev 서버는 스택트레이스·소스맵을 브라우저에 노출
- **영향**: 세션 탈취 시 관리자 포함 전 계정 도용. 내부 파일경로·쿼리 구조 노출
- **심각도**: High(실제 HTTPS 종단 구성은 미확인) · **개선**: 운영용 .bat을 `npm run build && npm run start`로 분리, `secure`는 `NODE_ENV` 대신 명시적 `.env`(예: `COOKIE_SECURE=1`)로 강제

### H-4. 임시 비밀번호가 만료되지 않고, 강제 변경 화면도 우회 가능

- **위치**: `app/actions/password-reset.ts:68~79`(만료 시각 컬럼·검사 없음) / 강제 리다이렉트가 `app/attendance/page.tsx:26`·`app/dashboard/page.tsx:23` **단 두 곳뿐**(전수 grep)
- **재현**: 임시 비밀번호로 로그인 → `/change-password`로 보내짐 → 주소창에 `/my-records`·`/leave`·`/records` 직접 입력 → **정상 이용**. 몇 달 뒤에도 그 임시 비밀번호로 로그인 가능
- **영향**: 문자로 보낸 임시 비밀번호가 유출되면(문자 열람·단말 분실) 기간 제한 없이 계정 탈취. 관리자 계정이면 회사 전체 근태·개인정보 노출
- **심각도**: High · **개선**: ①`tempPasswordExpiresAt` 추가 후 로그인 시 만료 검사 ②`getCurrentUser()` 또는 공통 레이아웃에서 `mustChangePassword` 일괄 차단

### H-5. 정정 승인이 열린 외출을 정리하지 않아 실근무가 매일 줄어들어 0까지 잠식

- **위치**: `app/actions/corrections.ts:99~123`(외출 무접촉) + `lib/worktime.ts:14`(`bEnd = b.endAt ?? now`)
- **재현**: 외출 시작 후 복귀·퇴근을 모두 잊음 → 다음날 "퇴근 18:00" 정정 신청 → 승인
- **실제**: 퇴근은 채워지지만 **열린 외출은 그대로 남는다.** 일반 퇴근 경로는 외출을 닫아주는데(attendance.ts:116~119) 정정 경로엔 그 처리가 없다. 이후 외출시간이 조회할 때마다 늘어 **그날 실근무가 볼 때마다 줄다가 0으로 고정**
- **영향**: 리포트·엑셀·내근태 전부 오염. 부가로, 정정으로 출퇴근 시각이 외출 구간 밖으로 이동해도 외출 전체가 그대로 차감된다
- **심각도**: High · **개선**: 정정 승인 트랜잭션에서 열린 외출을 새 퇴근시각으로 닫고, 근무구간 밖 외출은 경고·절단

### H-6. 퇴사한 부서장이 결재자로 남아 결재가 조용히 멈춤

- **심각도**: High · **개선**: 결재선 산출 시 재직자 필터 + 퇴사 처리 시 부서장·대결자 해제 및 본인 대기 단계 건너뛰기

### H-7. 리포트에 "기간 내 출근 0건" 직원이 아예 안 나옴 → 전 기간 결근자가 실종

## 4. 경미 (Low) — 참고

- **L-1** `근태관리_실행.bat`(git 추적됨)에 계정/비밀번호 문자열 하드코딩(`admin@skytech.co.kr / test1234` 등). 현재 DB에 해당 계정 없어 즉시 악용 불가하나 사규 위반, 재시드 시 부활 → 문구 삭제 권장
- **L-2** CSP(Content-Security-Policy) 헤더 없음. `dangerouslySetInnerHTML` 8곳은 전부 정적 SVG라 현재 XSS 없으나 방어선 부재
- **L-3** 비밀번호 정책이 "8자 이상"뿐(`12345678` 허용). 해시 자체는 적정(scrypt + timingSafeEqual)이나 **문서엔 bcrypt로 적혀 있어 코드-문서 불일치**
- **L-4** 지각·조퇴·결근 판정 로직이 **4곳에 각각 구현**(`lib/dayentries.ts` 중앙 허브 + `records`·`dashboard`·`reports` 인라인). 지금은 결과가 일치하지만 한 곳만 고치면 화면별 판정이 갈라지는 구조
- **L-5** 기간 파라미터 검증 블록(92일 캡)이 5곳 복붙, `MAX_DAYS`가 파일마다 로컬 상수 → 한 곳 누락 시 "화면엔 있는데 엑셀엔 없는" 불일치
- **L-6** SMS 기본 주소가 `http://`(암호화 없이 발송 계정·비번 전송) — 벤더 규격 확인 필요
- **L-7** 오전 반차 승인자가 대시보드 "미출근"에서 하루 종일 제외됨
