## 1. 배경 · 목적

### 1.1 왜 필요한가
- 원래 MVP 타깃은 **사무직 주간근무(09~18)**였으나, 실제 문의는 **교대근무 업체**(생산직·서비스업·병원 등)로 확장되고 있음.
- 교대근무는 시프티가 강한 시장이라, 진입 시 정면 경쟁이지만 **"쉽고 저렴한 중소기업용"** 포지션으로 공백을 노릴 수 있음.

### 1.2 현재 앱의 한계 (정확히)
- 출근/퇴근 기준시각이 **회사 전체 1쌍**([WorkRulesForm](../../webapp/app/settings/WorkRulesForm.tsx))뿐. 조별로 못 나눔.
- 지각·조퇴 판정([worktime.ts](../../webapp/lib/worktime.ts) `isLate`/`isEarlyLeave`)이 **"시:분(time-of-day)만 비교"** → **자정을 넘기는 야간근무를 정확히 판정 못 함**(코드 주석에도 명시).
- 직원별 예외는 **근무요일만** 지정 가능, 출근시각은 불가.

## 2. 범위 (Scope)

### 2.1 In (이번에 만든다)
1. **교대 정의**: 설정에서 2·3교대 선택 → 조별 출근·퇴근 기준시각(야간 넘김 포함) 입력.
2. **근무표**: 회사가 **고정 요일패턴** 또는 **순환 규칙(조 단위)** 중 선택 + **날짜 예외**로 누가 언제 어느 조인지 관리.
3. **직원 셀프 수정 + 이력 + 알림**: 직원이 **미래** 근무표를 직접 수정, 변경 시 이력·알림(부정 방지).
4. **판정 전환**: 지각·조퇴·실근무·결근을 **그날 조 기준 + 자정 넘김 정확 계산**으로.
5. **하위호환**: "교대 안 함"이면 지금과 100% 동일하게 동작.

### 2.2 Out (이번에 안 한다)
- ❌ **급여·수당 자동계산**(연장/야간/휴일 가산율, 통상임금) — 별도 조사 후 차기 단계.
- ❌ 근무표 **자동 생성/로테이션 자동화**(패턴 자동 배정) — 이번엔 **수동 배정**만.
- ❌ 교대조별 지각유예·기준 일 근무시간(사장님 결정: **회사 공통 유지**).
- ❌ 4교대 이상(이번엔 2·3교대. 확장은 차기).

## 3. 확정 결정사항 (사장님, 2026-07-19)

| # | 결정 |
|---|---|
| 1 | **로테이션** — 직원 고정 배정이 아니라 **날짜별 근무표**로 조를 바꿈. |
| 2 | **야간조 있음** — 자정을 넘기는 조(예 22시~익일 06시) 지원 필요. |
| 3 | **지각유예·기준 일 근무시간(8h)은 회사 공통** (조별 아님). |
| 4 | **근무표 = 기본 배정(자동) + 날짜 예외(덮어쓰기)** — 한 번 정하면 변경 전까지 계속 이어짐. 특정 날만 덮어쓰기. |
| 5 | **직원 셀프 수정 허용**(관리자 대체) — 단 **미래 날짜만**, 즉시 반영, **알림+이력** 남김, 관리자 되돌리기 가능(부정 방지). |
| 6 | **기본 배정 방식 2가지 지원(회사별 선택)** — ⓐ 고정 요일패턴 / ⓑ **순환 규칙(조 단위)**. |
| 7 | **순환은 조(A/B/C) 단위** — 직원은 조에 소속, 조 전체가 규칙(순서·단위·시작일)에 따라 한 칸씩 자동 이동. 관리자 개입(예외) 가능. |

## 4. 사용자 시나리오

1. **관리자**가 [설정]에서 "3교대"를 켜고 → `1교대 06:00~14:00 / 2교대 14:00~22:00 / 3교대(야간) 22:00~06:00`를 입력·저장.
2. **관리자**가 [근무표]에서 이번 주 배정: 홍길동=1교대(월~금), 김철수=3교대(월~금) …
3. **직원**은 평소처럼 출퇴근만 찍는다(방식 변화 없음).
4. 김철수가 야간조인 날 22:10에 출근 → **자기 조(22:00) 기준 +유예 초과 → 지각**으로 정확히 표기. 익일 06:05 퇴근 → 자정 넘겨도 **실근무 약 8시간**으로 정확 집계.
5. **관리자**가 [근태현황]·[리포트]에서 조 기준으로 정리된 지각·실근무를 확인.

## 5. 기능 상세

### 5.1 [설정] 교대 정의 (Phase 1)
- [근무요일] 오른쪽에 **"교대근무" 드롭박스**: `안 함 / 2교대 / 3교대`.
- 선택 시 **아래 출근·퇴근 기준시각 영역이 조 개수만큼 자동 확장**, 각 줄 앞에 `1교대·2교대·3교대` 라벨.
  - 각 조: **이름(선택)** · **출근 기준시각** · **퇴근 기준시각** · **야간(자정 넘김) 여부는 시각으로 자동 판단**(퇴근<출근이면 익일로 간주).
- **지각유예·기준 일 근무시간**은 조별로 나누지 않고 **기존처럼 회사 1개** 입력 유지.
- "안 함" 선택 시 기존 단일 출근/퇴근 시각 그대로(하위호환).

### 5.2 [근무표] 기본 배정 생성(방식 선택) + 날짜 예외 (Phase 2) — 신규 화면
근무표는 **[기본 배정] 위에 [날짜 예외]를 덮는** 두 층 구조다(결정 4·6·7). 회사는 기본 배정 **방식을 하나 선택**한다:

**방식 ⓐ — 고정 요일패턴** (고정조·사무직형)
- 직원마다 요일→조(예 홍길동 월~금=1조, 토·일=휴무). 한 번 정하면 매주 자동 반복.

**방식 ⓑ — 순환 규칙(조 단위)** (공장·병원 3교대형)
- 직원을 **A/B/C조**에 소속시킨다.
- **순환 규칙** = ① 순환 순서(1조→2조→3조→1조) ② 이동 단위(일/주/월) ③ 시작 기준일(anchor) ④ 조별 시작 단계(A=1조·B=2조·C=3조).
- 규칙에 따라 **조 전체가 자동으로 한 칸씩 이동**(예 매주: A조 이번주 1조→다음주 2조→…). 손으로 매주 안 짜도 됨.

**공통 — 날짜 예외(덮어쓰기)**
- 특정 날만 기본 배정과 다르게(그날 조 변경·휴무). 관리자·직원(미래만) 수정 → 이력·알림(§5.4).
- **그날 실제 조 = 예외(있으면) → 없으면 기본 배정(ⓐ 요일패턴 또는 ⓑ 순환 계산) → 없으면 휴무.** (미배정 개념 없음)

**화면**: 관리자 [근무표] — 방식 ⓐ면 요일패턴 편집 / ⓑ면 조 배정+순환규칙 설정. 공통으로 **주(week) 그리드**(행=직원, 열=날짜, 칸=조/휴무)에서 그날 실제 조 확인·예외 지정. 주 이전/다음, 직원 검색.
- ※ 이번엔 방식 ⓐ·ⓑ **정의·수동 예외**까지(더 복잡한 자동배정·4교대+는 차기).

### 5.4 직원 셀프 수정 + 이력 + 알림 (Phase 2') — 부정 방지 설계
사장님 결정 5. **관리자가 못 바꿀 상황 대비, 직원이 자기 근무표(날짜 예외)를 직접 수정**하되 무결성을 지킨다.
- **미래 날짜만** 수정 가능. **오늘·과거는 잠금**(이미 지난 날의 지각·결근을 사후에 지우지 못하게 — 핵심 안전장치).
- **즉시 반영**(승인 대기 없음) + **변경 이력 저장**(누가·언제·무엇을 어떻게: 예 "07-25 1교대→야간조").
- **알림센터에 기록** — 관리자에게 "직원이 근무표를 변경함" 알림. 관리자가 **되돌리기** 가능.
- 직원은 **자기 것만** 수정(타인 근무표 불가). 회사 격리·권한 검증 서버에서.
- (선택 차기) 변경 횟수 제한·사유 입력 등 추가 통제.

### 5.3 판정 로직 전환 (Phase 3) — 핵심
- 지각·조퇴·실근무·결근을 **"그 직원의 그날 근무표 조"**의 출근/퇴근 기준시각으로 판정.
- **자정 넘김 정확 계산**: 현재 "시:분 비교"를 버리고, **예정 출근시각과 실제 출근시각의 절대 분(minute) 차이**로 지각을, 실근무는 이미 (퇴근−출근) 방식이라 자정 넘겨도 정확(단, 지각/조퇴 판정만 조 기준으로 새로 계산).
- 반영 화면: [근태현황](../../webapp/app/records/page.tsx) · [리포트](../../webapp/app/reports/page.tsx) · [대시보드 오늘 알림](../../webapp/app/dashboard/page.tsx) · [내근태/직원상세](../../webapp/app/components/DetailTable.tsx).

## 6. 데이터 모델 초안 (스키마)

> 최종 필드는 설계(04_architecture) 단계에서 확정. 아래는 방향.

```
// 회사 설정에 교대 사용 여부·근무표 방식
Company.shiftMode     Int?     // null/0 = 교대 안 함, 2 = 2교대, 3 = 3교대
Company.scheduleType  String?  // "fixed"(요일패턴) | "rotation"(순환 규칙)

// 교대조 정의 (회사당 2~3개)
model Shift {
  id         String  // 
  companyId  String
  order      Int     // 1,2,3 (표시 순서·라벨)
  name       String? // "오전조" 등(선택)
  startTime  String  // "HH:MM"
  endTime    String  // "HH:MM" (endTime<startTime 이면 익일=야간조)
}

// [방식 ⓐ 고정] 요일별 기본 패턴 (직원 × 요일 → 조) — 반복의 기준
model ShiftPattern {
  companyId String
  userId    String
  dayOfWeek Int     // 0=일 … 6=토
  shiftId   String? // null = 휴무
  @@unique([userId, dayOfWeek])  // 요일당 1개
}

// [방식 ⓑ 순환] 조(A/B/C) — 직원이 소속되는 그룹
model ShiftGroup {
  id        String
  companyId String
  order     Int     // 0,1,2(=A,B,C) — 시작 단계 offset로도 사용
  name      String? // "A조" 등
}
// User.shiftGroupId String?  — 직원의 소속 조(순환 방식일 때)

// [방식 ⓑ 순환] 순환 규칙 (회사당 1개)
model RotationRule {
  companyId  String
  order      String  // 순환 순서, 예 "1,2,3"(shift 순서)
  unit       String  // "day" | "week" | "month"
  anchorDate String  // "YYYY-MM-DD" 시작 기준일
  // 조별 시작단계 = ShiftGroup.order (A=0,B=1,C=2)에서 파생
}

// ② 날짜 예외 (직원 × 날짜 → 조) — 그날만 패턴을 덮어씀
model ShiftAssignment {
  id        String
  companyId String
  userId    String
  date      String  // "YYYY-MM-DD"
  shiftId   String? // null = 휴무
  editedBy  String  // "admin" | "self"(직원 셀프수정)
  @@unique([userId, date])  // 하루 1예외
}

// ③ 근무표 변경 이력 (특히 직원 셀프수정 감사) — 알림·되돌리기 근거
model ShiftChangeLog {
  id        String
  companyId String
  userId    String   // 대상 직원
  date      String
  fromShift String?  // 변경 전 조(라벨)
  toShift   String?  // 변경 후 조(라벨)
  actor     String   // "admin" | "self"
  createdAt DateTime
}
```
- **그날 실제 조 계산** = ShiftAssignment(date 예외) → 없으면 **기본배정**[ⓐ ShiftPattern(요일) 또는 ⓑ 순환계산] → 없으면 휴무.
  - **순환계산(ⓑ)**: `경과 단위 수 = (그 날짜 − anchorDate) / unit`; `조의 현재 shift index = (ShiftGroup.order + 경과 단위 수) mod 조 개수` → order 배열로 shift 결정. (예 주 단위: 이번주 대비 몇 주 지났는지로 A/B/C조가 한 칸씩 이동)
- 직원 셀프수정은 ShiftAssignment(미래 date)만 생성/수정 + ShiftChangeLog 기록 + 알림.
- 이력·알림은 **기존 AccessEvent/알림센터 재사용 검토**(신규 최소화) — 설계 단계에서 확정.
- 마이그레이션은 **모두 nullable·기본값**으로 하위호환(기존 회사=교대 안 함).
