## 1. 핵심 개념 한 장

```
[회사 설정]
  shiftMode: 안함 | 2교대 | 3교대
  scheduleType: fixed(요일패턴) | rotation(순환)
  Shift[]: 조별 출근~퇴근 기준시각 (endTime<startTime → 야간=익일)

[기본 배정 생성기] ── fixed  → ShiftPattern(직원×요일→shift)
                   └─ rotation → ShiftGroup(A/B/C) + RotationRule + User.shiftGroupId
        │  (그날 각 직원의 '기본 shift')
        ▼
[예외 override] ShiftAssignment(직원×날짜→shift, editedBy) + ShiftChangeLog + 알림
        │
        ▼
[그날 실제 shift]  ← 판정·리포트·대시보드가 이 값 하나만 사용
```

**해석 우선순위(resolveShift):** 예외(ShiftAssignment) → 기본배정(fixed 또는 rotation) → 휴무(null)

## 2. 데이터 모델 (Prisma — 최종, 마이그레이션 대상)

> 모두 **nullable/기본값**으로 추가 → 기존 회사(shiftMode=null)는 100% 현행 동작(하위호환).

```prisma
model Company {
  // ... 기존 필드 ...
  shiftMode     Int?    // null=교대 안 함, 2, 3
  scheduleType  String? // "fixed" | "rotation" (shiftMode 있을 때만 의미)
  shifts        Shift[]
  rotationRule  RotationRule?
}

model User {
  // ... 기존 필드 ...
  shiftGroupId  String?     // 순환(rotation) 방식일 때 소속 조. fixed면 미사용
  shiftGroup    ShiftGroup? @relation(fields: [shiftGroupId], references: [id])
  shiftPatterns ShiftPattern[]
}

// 조별 근무시간 정의 (회사당 shiftMode개)
model Shift {
  id        String  @id @default(cuid())
  companyId String
  company   Company @relation(fields: [companyId], references: [id])
  order     Int     // 1,2,3 (표시·순환 순서 기준)
  name      String? // "오전조" 등(선택)
  startTime String  // "HH:MM"
  endTime   String  // "HH:MM" — endTime<=startTime 이면 익일(야간조)
  @@unique([companyId, order])
}

// [fixed] 요일 패턴
model ShiftPattern {
  id        String  @id @default(cuid())
  companyId String
  userId    String
  user      User    @relation(fields: [userId], references: [id])
  dayOfWeek Int     // 0=일 … 6=토
  shiftId   String? // null=휴무
  @@unique([userId, dayOfWeek])
}

// [rotation] 조(A/B/C)
model ShiftGroup {
  id        String @id @default(cuid())
  companyId String
  order     Int    // 0,1,2 (=A,B,C) — 시작단계 offset
  name      String?
  users     User[]
  @@unique([companyId, order])
}

// [rotation] 순환 규칙 (회사당 1)
model RotationRule {
  companyId  String @id
  company    Company @relation(fields: [companyId], references: [id])
  orderCsv   String // 순환 순서(shift.order들), 예 "1,2,3"
  unit       String // "day" | "week" | "month"
  anchorDate String // "YYYY-MM-DD"
}

// 예외(덮어쓰기) — 관리자/직원 수정
model ShiftAssignment {
  id        String  @id @default(cuid())
  companyId String
  userId    String
  date      String  // "YYYY-MM-DD"
  shiftId   String? // null=휴무
  editedBy  String  // "admin" | "self"
  createdAt DateTime @default(now())
  @@unique([userId, date])
  @@index([companyId, date])
}

// 변경 이력(감사) — 셀프수정 추적·되돌리기 근거
model ShiftChangeLog {
  id        String   @id @default(cuid())
  companyId String
  userId    String   // 대상 직원
  date      String
  fromLabel String?  // 변경 전 조 라벨
  toLabel   String?  // 변경 후 조 라벨
  actor     String   // "admin" | "self"
  actorId   String   // 수정 실행자 userId
  createdAt DateTime @default(now())
  @@index([companyId, createdAt])
}
```

## 3. 핵심 알고리즘 — resolveShift(user, date)

```ts
// 반환: Shift | null(휴무). 그날 그 직원이 어느 조인지.
function resolveShift(user, dateISO, ctx): Shift | null {
  // 1) 예외 우선
  const ex = ctx.assignmentsByUserDate.get(`${user.id}|${dateISO}`);
  if (ex !== undefined) return ex.shiftId ? ctx.shiftById.get(ex.shiftId) : null;

  // 2) 기본 배정
  if (ctx.scheduleType === "fixed") {
    const dow = dowOf(dateISO);
    const p = ctx.patternByUserDow.get(`${user.id}|${dow}`);
    return p?.shiftId ? ctx.shiftById.get(p.shiftId) : null;
  }
  if (ctx.scheduleType === "rotation") {
    if (!user.shiftGroupId) return null;
    const group = ctx.groupById.get(user.shiftGroupId);
    const steps = elapsedUnits(ctx.rule.anchorDate, dateISO, ctx.rule.unit); // 정수(경과 단위 수)
    const order = ctx.rule.orderCsv.split(",").map(Number);                  // [1,2,3]
    const idx = ((group.order + steps) % order.length + order.length) % order.length;
    return ctx.shiftByOrder.get(order[idx]);
  }
  return null;
}
```
- **elapsedUnits**: 주=월요일 00시 경계(결정 H, 주52와 동일). anchorDate가 속한 주부터 몇 주 지났는지. 일/월도 동일 원리.
- **성능**: 화면당 한 번 회사의 Shift/Pattern/Group/Rule/기간내 Assignment를 로드해 Map으로 만들고, 직원×날짜 루프에서 O(1) 조회.

## 4. 판정 로직 변경 (자정 넘김 핵심)

현재 [worktime.ts](../../webapp/lib/worktime.ts) `isLate`/`isEarlyLeave`는 "시:분만 비교" → 야간조 오판. **시프트 기준 새 함수**로 대체(교대제일 때만; 비교대는 기존 유지).

```ts
// 예정 출근 = 그날 shift.startTime을 그 날짜에 얹은 절대시각.
// 지각 = 실제 clockIn > 예정출근 + graceMin (분 절대 비교). 야간조도 정확.
function isLateByShift(clockIn, dateISO, shift, graceMin): boolean {
  const planned = atDate(dateISO, shift.startTime);           // 예정 출근 절대시각
  return diffMin(clockIn, planned) > graceMin;
}
// 조퇴 = 실제 clockOut < 예정 퇴근. 예정퇴근은 endTime<=startTime이면 익일로 얹음.
function isEarlyLeaveByShift(clockOut, dateISO, shift): boolean {
  const plannedOut = shift.endTime <= shift.startTime
    ? atDate(nextDay(dateISO), shift.endTime)                 // 야간=익일 퇴근
    : atDate(dateISO, shift.endTime);
  return clockOut < plannedOut;
}
```
- **실근무**: 기존 `workedMinutes`(퇴근−출근−외출)는 자정 넘겨도 이미 정확 → **변경 없음**.
- **날짜 귀속(결정 A)**: 야간조 근무는 **출근일(clockIn 날짜) 기준**으로 집계(기존 `toISODate(clockIn)`와 동일 — 변경 없음).
- **결근(결정 C)**: 교대제면 "그날 resolveShift가 근무(shift≠null)인데 출근기록 없음 = 결근". 비교대는 기존(근무요일) 유지.

## 9. 테스트 계획 (핵심 경계값)

- 자정 경계: 야간조 22:00 출근→익일 06:00 퇴근 지각/조퇴/실근무 정확.
- 주 경계: anchor 기준 주 바뀔 때 조 이동(월요일 00시).
- 순환: 3조 3교대 A/B/C가 서로 다른 조로 매주 이동, mod 순환 정확.
- fixed: 요일별 패턴·휴무.
- 예외 우선·셀프수정 과거잠금·타사 격리.
- **하위호환**: 비교대 회사 지각/조퇴/결근/실근무 회귀 0.
- 서버 TZ=Asia/Seoul 전제(자정 계산 민감 — 재확인).
