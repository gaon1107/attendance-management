## 1. 접근 방식과 이유

### 1-1. 회사 계정 = `role:"admin"` + `isOwner:true`

새 역할(`owner`)을 만들지 **않는다**. 권한 검사가 66개 파일 117군데에 흩어져 있어, 새 역할을 만들면 그 전부를 고쳐야 하고 하나만 빠져도 회사 계정이 화면에서 튕긴다.

```
회사 계정   role="admin", isOwner=true    ← 마스터 키. 아무도 지우거나 강등 못 함
사람 관리자  role="admin", isOwner=false   ← 실무. 여러 명 가능, 권한 동일
직원        role="employee"
```

이렇게 하면 **117군데를 한 줄도 안 고친다**(회사 계정도 admin이므로 전부 통과).

### 1-2. 🔴 근태 집계 필터 교체 (핵심)

지금 9군데가 `role:"employee"`로 걸러서 **관리자를 근태 집계에서 뺀다.** 관리자를 여러 명 만들 수 있게 되면 그 사람들이 통째로 사라진다.

```
[지금]  where: { role: "employee" }        → 관리자 전부 제외
[바꿈]  where: { isOwner: false }          → 사람은 전부 포함, 회사 계정만 제외
```

**⚠️ 이 변경으로 달라지는 것**: 지금 관리자인 **박성헌 님이 대시보드 출근 현황·연차 현황에 새로 나타납니다.** 관리자도 근로자이므로 이게 옳은 동작이지만, 화면 숫자가 달라지니 미리 알려드립니다. (원치 않으시면 "근태 집계 제외" 체크박스를 직원별로 두는 방식으로 바꿀 수 있습니다 — 메모 주세요.)

### 1-3. 가입 화면

```
회사명            *필수
사업자등록번호     *필수  → 국세청 진위확인 (가짜·폐업이면 가입 거부)
담당자 이름        *필수
담당자 휴대폰      *필수  (형식만 검사. 문자 인증은 2차)
회사 계정 이메일    *필수  (= 로그인 아이디)
비밀번호          *필수  (8자 이상)
[ ] 이용약관 동의        *필수
[ ] 개인정보 수집·이용 동의 *필수
```

- 사업자등록번호는 **국세청 공공데이터 API**(무료)로 진위·폐업 여부를 확인합니다. 이미 공휴일 API로 같은 포털을 쓰고 있어 계정을 새로 만들 필요가 없습니다.
- **API가 죽어 있으면 가입을 막지 않고 "확인 보류"로 통과**시킵니다(fail-open). 국세청 서버 장애로 신규 고객을 놓치는 것이 더 큰 손해입니다. 보류 건은 [회사정보]에 표시해 나중에 확인합니다.

### 1-4. 이메일·문자 인증은 왜 2차인가

- **메일 보내는 수단이 저장소에 아예 없습니다.** 지금 만들면 "인증 메일이 안 오는 화면"이 됩니다.
- 문자는 코드(아이원24)는 있으나 **계정 키가 없어 발송이 안 됩니다**(정소장님 확인 대기 중).
- 사업자등록번호 확인만으로도 "아무나 막 가입"은 대부분 막힙니다. 남의 사업자번호를 쓰는 경우는 결제 단계에서 걸러집니다.

## 3. 🛡️ 사이드 이펙트 방어

| 위험 | 왜 생기나 | 대응 |
|---|---|---|
| 🔴 **근태 숫자가 틀어진다** | 9군데 필터 교체 | 교체 전후 **같은 데이터로 인원수·연차일수를 비교**해 차이가 "관리자 인원수"와 정확히 일치하는지 확인 |
| 🔴 **회사가 관리자 0명이 된다** | 마지막 관리자를 해제·퇴사 | 회사 계정은 해제·퇴사 **불가**로 못 박음(서버에서 차단). 회사 계정이 항상 남으므로 잠기지 않음 |
| **회사 계정이 화면에서 튕긴다** | 권한 검사 누락 | `role="admin"` 그대로라 117군데 무영향. 실제로 주요 화면 5개를 열어 확인 |
| **회사 계정이 직원 명단에 섞인다** | 필터 교체 부작용 | `isOwner:false` 조건으로 회사 계정만 정확히 제외 |
| **기존 뉴가온 데이터** | 회사 계정이 없음 | 1회용 정리 스크립트로 회사 계정 생성 + 박성헌은 관리자 유지. **작업 전 DB 백업 필수** |
| **가입이 막힌다** | 국세청 API 장애 | fail-open(확인 보류로 통과) |
| 다른 회사 데이터 침범 | — | 모든 신규 조회에 `companyId` 필수. 검수 항목 |
