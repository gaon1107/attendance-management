## 0. 목적과 범위

- **목적**: 근무일정 밖 시간에 직원 PC를 잠그고, 승인된 연장근무만 해제하는 PC-OFF 기능을 기존 근태 SaaS(webapp, Next.js+Prisma+SQLite)에 추가한다.
- **범위**: Phase 0(프로토타입) → 1(서버) → 2(에이전트 MVP) → 3(상품화). **각 Phase 종료 시 대표 승인 후 다음 진행** — 한 번에 다 만들지 말 것.
- **범위 아님(만들지 말 것)**: 화면캡처·키로깅·앱 사용목록 수집 / 원격조종 / 사이트 차단 / Mac 지원 / 교대근무(Shift) 연동 / 전원 shutdown 모드 / 이석 측정(추후 별도 지시) / 워치독(강제종료 방지). 이 중 어떤 것도 "하는 김에" 추가 금지.

## 1. 🚫 절대 규칙 — 기존 프로그램 보호 (위반 시 작업 중단·롤백)

1. **수정 금지 파일**(읽기·호출만 허용):
   - `lib/approval-server.ts` (결재 엔진 — 6종 신청·밀린결재 현황판이 공유)
   - `lib/worktime.ts`, `lib/overtime.ts`, `lib/overtime-week.ts` (실근무·주52 계산)
   - `app/actions/overtime.ts` (기존 초과근무 신청·승인 — 브라우저용으로 그대로 둔다)
   - `lib/session.ts` (브라우저 세션 — 에이전트 인증은 **별도 파일**로 만든다)
   - 기존 6종 신청 화면·결재함·밀린결재 현황판 전부
2. **DB는 add-only**: 기존 컬럼 수정·삭제·이름변경 금지. 새 필드는 전부 기본값 있는 nullable/default로 추가(기존 데이터·화면 무영향). `prisma migrate dev`로 마이그레이션 생성, 실행 전 `dev.db` 백업.
3. **기존 파일 수정은 딱 3곳만 허용**(각각 최소 diff):
   - `prisma/schema.prisma` — 필드·모델 추가
   - `app/settings/page.tsx` — PC-OFF 설정 카드 1개 삽입(기존 카드 순서·코드 불변)
   - `app/components/Sidebar.tsx` — 관리자 메뉴 1개 추가(라벨 **4글자 이하**, 기존 라벨 규칙: 305줄 파일, 기존 항목 배열에 1개 push만)
   - 이 외 기존 파일을 고쳐야 하는 상황이 오면 **멈추고 보고**(safe-coding-skill 절차).
4. 비밀값(토큰 등) 소스·문서·로그에 평문 기록 금지. 에이전트 토큰은 DB에 **해시만** 저장.
5. Phase마다 커밋 분리. `tsc`·`eslint` 0 에러 아니면 커밋 금지.

| 필요 기능 | 반드시 이걸 쓸 것 (재구현 금지) | 위치 |

| 설정 폼 UI 패턴 | `app/settings/WorkRulesForm.tsx` 구조 복제 | `app/settings/` |

**⚠️ 핵심 주의 — 초과근무 신청 재사용 방법**: 기존 `requestOvertime`(`app/actions/overtime.ts:14`)은 `getCurrentUser()`(쿠키 세션)에 묶여 있어 **에이전트 API에서 직접 호출 불가**. 해결책은 기존 함수 수정이 아니라, 에이전트용 API 라우트가 같은 3단계(검증 `isValidHm`·`parseYmd` → `prisma.overtimeRequest.create` → `createApprovalStepsIfNeeded`)를 **같은 lib 함수들로 조립**하는 것. 검증 규칙(500자 사유 제한, start==end 금지, 익일 허용)도 동일하게 맞출 것. `requestOvertime`을 고치거나 공용 코어로 리팩토링하지 말 것(영향 범위가 커짐).

## 4. Phase 1 — 서버 쪽 (webapp 안, 에이전트 없이 검증 가능)

### 4-1. DB (schema.prisma에 추가만)
- Company: `pcOffOn Boolean @default(false)` / `pcOffMode String @default("lock")` / `pcOffDelayMin Int @default(30)` / `pcOffNotifyMins String @default("10,5")` / `pcOffTempUseMin Int @default(30)` / `pcOffTempUsePerDay Int @default(1)`
- User: `pcOffExempt Boolean @default(false)`
- 신규 `AgentDevice`(id/companyId/userId/deviceName/tokenHash @unique/agentVersion/pairedAt/lastSeenAt/revokedAt) — `@@index([companyId])`, `@@index([userId])`
- 신규 `AgentPairCode`(id/userId/code/expiresAt/usedAt) — 6자리 숫자, 5분 유효, 1회용
- 신규 `AgentEvent`(id/companyId/userId/deviceId/type/at/meta String?) — `@@index([companyId, at])`
- 검증: 마이그레이션 후 기존 표 33개 행수 동일 확인(백업본 대조).

### 4-2. 신규 파일만으로 구성 (기존 무접촉)
| 파일 | 내용 |
|---|---|
| `lib/agent-auth.ts` | 토큰 발급(32byte랜덤→sha256 해시 저장)·검증(`Authorization: Bearer`)·revoke. **lib/session.ts 수정 금지** |
| `lib/pcoff-policy.ts` | 정책 조립: 회사 설정+오늘·내일 휴일(`loadOffDays`)+내 승인 연장근무+`serverTime` 반환 |
| `app/api/agent/pair/route.ts` | POST: 코드 검증→AgentDevice 생성→토큰 1회 평문 반환 |
| `app/api/agent/policy/route.ts` | GET: 토큰 인증→정책 JSON. `revokedAt` 있으면 401 |
| `app/api/agent/events/route.ts` | POST: 사건 배열(최대 100건) 저장 + `lastSeenAt` 갱신 |
| `app/api/agent/overtime/route.ts` | POST: §2 주의사항 방식으로 연장신청 생성(결재선 포함) |
| `app/actions/pcoff.ts` | 설정 저장(관리자 가드)·페어코드 발급·기기 revoke — `settings.ts` 패턴 |
| `app/settings/PcOffForm.tsx` | 설정 카드(WorkRulesForm 패턴) |
| `app/pc-devices/page.tsx` | 관리자 [PC관리]: 기기 목록(온라인=lastSeenAt 10분 내)·revoke·이벤트 로그 |
| [내 계정] 카드 | 연결코드 발급 + 내 기기 목록(account 페이지에 컴포넌트 추가 — 기존 카드 무수정) |

- 모든 API: 입력 검증·에러 JSON(`{error}`)·회사/본인 소속 확인(멀티테넌트 격리) 필수. rate 고려해 events는 배치만 허용.
- **완료 기준**: ①`curl`(또는 스크립트)로 4개 API 정상+비정상(만료코드·revoked 토큰·타사 접근) 케이스 통과 로그 제출 ②설정 저장/재로딩 화면 확인 ③**기존 회귀**: 초과근무 신청→결재함 승인→기존 화면 정상(무변화) 증명.

## 5. Phase 2 — 에이전트 MVP (Phase 0 확정 프레임워크)

- 모듈: 정책 폴링(5분, 잠금 중 1분)+로컬 캐시(DPAPI 암호화) / 판정기(근무요일·시각+유예+승인연장+일시사용, **서버시각 보정**) / 알림 토스트 / 잠금화면(연장신청 미니폼·일시사용(사유 필수)·새로고침) / 이벤트 큐(오프라인 재전송) / 트레이(수집항목 고지).
- **안전 규칙**: 캐시 정책 없으면 절대 잠그지 않음(fail-open). 시각 판정은 `serverTime`과의 오프셋 기준(PC 시계 조작 무력화). `pcOffOn=false`·`pcOffExempt=true`면 완전 휴면.
- **완료 기준(시나리오 4종 실기기 증명)**: ①정상 퇴근: 알림 2회→유예 후 잠금→다음 근무일 해제 ②연장: 잠금화면 신청→웹 결재 승인→1분 내 해제→승인 종료시각에 재잠금 ③일시사용: 30분 해제+사유가 [PC관리] 로그에 표시+횟수 제한 작동 ④오프라인: 네트워크 차단 상태에서 캐시 정책으로 잠금+이벤트 복구 전송.
