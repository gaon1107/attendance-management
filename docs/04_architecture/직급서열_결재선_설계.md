# 직급 서열 기반 결재선 — 설계서 (v2 최종, 2026-07-20)

> 목적: "부서 안 여러 단계(대리→과장→부장) + 부서 간(부서장→본부장→대표)"를 모두 담는 결재선.
> **최종 방식 = 혼용(B)**: 부서 안은 **직원이 직급 상급자 중 고름**, 부서장 위쪽은 **조직도로 자동 연결**.
> 원칙: **add-only·회귀 0**. single/deptline 모드와 기존 데이터는 절대 안 건드린다.

## 확정 결정 (사장님, 2026-07-20)
1. 직급 체계 = **회사별 직급 편집(새 표)** — 회사가 자기 직급 사다리를 직접 만든다.
2. 결재선 = **직원이 상급자 중 고름**(부서 내), **부서장 위는 조직도 자동**(= 혼용 B).
3. 미설정 처리 = 아래 4장(혼용이라 의미가 바뀜 — 확인 필요).
4. 후보 범위 = **같은 부서 상위레벨**(직원이 고르는 부분).

---

## 1. 한 줄 정의
`custom`(상신자 지정) 모드의 결재선을 **[직원이 고른 부서 내 상급자] + [조직도 자동 상향(부서장→대표)]** 두 조각을 이어 만든다.

**예 — 영업1팀 김사원 휴가 신청:**
`김사원 → (직원 지정) 이대리 → 박과장 → (조직도 자동) 최부장(부서장) → 정본부장 → 대표`
- 앞부분(대리·과장)은 김사원이 편집기에서 고름.
- 뒷부분(부서장→대표)은 조직도(부서장·상위부서)로 자동.

---

## 2. 데이터 변경 (add-only)

### 2-1. 신규 표 `JobGrade` (회사별 직급 사다리)
| 필드 | 설명 |
|---|---|
| id / companyId | 회사 격리 |
| name | 직급명 (예: 사원·대리·과장·부장) |
| level Int | 서열(클수록 상급). 회사가 순서 정함 |
- 회사마다 자기 직급을 만들고 순서를 정한다. (표준 사다리 기본 제공 후 편집 가능하게)

### 2-2. `User.jobGradeId String?` 신규 (nullable)
- 직원이 속한 직급. `null` = 미지정 → 직급 결재선에서 제외(관리자 폴백).
- 기존 `User.position`(자유 텍스트)은 유지(표시용). 서열 비교는 `jobGrade.level`로.

### 2-3. 기존 표 무변경
- `Department`(부서장·상위부서·전결)·`ApprovalLineTemplate`·`ApprovalStep` 전부 재사용.

---

## 3. 결재선 계산 (혼용)

### 3-1. 직원이 고르는 부분 — 후보 = "같은 부서 상위레벨"
- 후보 = **같은 부서**에서 `jobGrade.level`이 **나보다 높은** 재직자. (본인·퇴사·중복 제외)
- 부서장(headUserId)은 뒤에서 조직도가 자동으로 넣으므로 후보에서 제외(중복 방지). → 직원은 부서장 "아래" 중간 상급자(대리·과장)만 고른다.
- 직원이 편집기에서 순서대로 저장(`ApprovalLineTemplate`).

### 3-2. 자동으로 붙는 부분 — 조직도 상향 (기존 buildApprovalChain 재사용)
- 신청자 부서의 **부서장** → 상위 부서장 → … → 대표. (전결권자 지정 시 거기서 종결)

### 3-3. 최종 체인 = [직원 지정] + [조직도 자동], 중복 제거·본인 제외·순서 보존
- 부서장이 신청하면: 부서 내 상급자 없음 → 직원 지정 0 → 조직도가 상위 부서장부터 자동. (부서장도 위로 올라감 ✔)
- 대표가 신청하면: 위가 없음 → 체인 0 → **전결(자동 확정)**.

---

## 4. "미설정·최상위" 처리 (혼용이라 의미가 바뀜 — 확인)

혼용에서는 **직원이 부서 내 상급자를 안 골라도, 조직도(부서장→대표)가 항상 바탕에 깔립니다.** 그래서 "승인자 없음"이 거의 안 생깁니다.

| 신청자 상태 | 처리 |
|---|---|
| 조직도(부서장·상위부서) 설정됨 + 부서 내 상급자 **안 고름** | 조직도대로 자동 진행(부서장→대표). **차단 아님** |
| 부서 내 상급자가 있는데 안 고름 | **안내**(강제 차단 X): "부서 내 결재자를 지정할 수 있습니다" |
| 조직도도 미설정 + 지정도 없음 | 관리자 단독 승인 폴백(현행) |
| 진짜 최상위(대표) | 전결(자동 확정) |

> ⚠️ **바뀐 점:** 앞서 "미설정=차단"으로 정했지만, 혼용에서는 조직도가 바탕이라 **강제 차단이 필요 없어지고 "안내"로 완화**하는 게 자연스럽습니다. (원하시면 "부서 내 상급자가 있는데 안 고르면 차단"으로 강하게 갈 수도 있음 — 확인)

## 5. 화면(UI) 변경
1. **직급 관리(신규, 관리자)**: 회사 직급 사다리 추가/이름/순서 편집. ([직원관리] 또는 [설정] 하위)
2. **직원 상세 `ProfileForm`**: 직급을 회사 직급 드롭다운으로 선택(jobGradeId 저장). 기존 자유 텍스트 병행/대체.
3. **조직도 `DepartmentManager`**: 부서장·상위부서 설정을 **custom 모드에서도** 노출(현재 deptline 전용).
4. **직원 결재선 편집기 `ApprovalLineEditor`**: 후보 = 같은 부서 상위레벨. "부서장 위는 자동 결재" 안내.
5. **신청 폼 6종**: 미설정 안내(강제 차단 채택 시 제출 차단).

## 6. 회귀오류 방지 (핵심)
- **스키마 add-only**: `JobGrade` 신규 표 + `User.jobGradeId` nullable → 기존 회사·직원 전부 무영향(회귀 0).
- **모드 격리**: 변경은 **custom 분기에만**. `single`·`deptline` 경로·판정 무접촉.
- **엔진 무수정**: `advanceApproval`·`ApprovalStep`·결재함·진행표시·6종 신청 재사용. 조직도 자동부는 검증된 `buildApprovalChain` 재사용.
- **기존 custom 저장 데이터**: 후보 규칙 교체로 규칙 밖 인원은 신청 시 자동 제외(기능①과 동일 안전 방식).
- **position 라벨·기존 데이터 보존**: 새 표/필드만 추가.
- **테넌트 격리**: 모든 신규 쿼리 companyId.
- **회귀 검증(임시 라우트)**: single·deptline 라운드트립 / 혼용 체인 정확성(직원지정+조직도자동 이어붙임·중복제거·순서) / 부서장 신청 상향 / 대표 전결 / 직급 미지정 폴백 / 테넌트 격리. 검증 후 임시데이터 전삭.

---

## 7. 구현 단계 (제안 — 단계별 커밋·검수)
- **1단계 · 직급 체계**: `JobGrade` 표 + 직급 관리 UI + 직원 직급 배정 + 표시. (결재 로직 무접촉, 저위험)
- **2단계 · 혼용 체인**: custom 후보=같은부서 상위레벨, `createApprovalStepsIfNeeded` custom = [직원지정]+[조직도자동] 이어붙임, 부서장 상향·대표 전결. 조직도 UI를 custom에 노출.
- **3단계 · 안내/차단 + 검증 마무리**: 신청 폼 안내, 전체 회귀 검증.
- 각 단계: 구현 → tsc·eslint·임시라우트 → code-reviewer → 커밋.
