## 1. 구성도 (전체 그림)

```
[직원 모바일 웹]     [관리자 PC 웹]
        │                 │
        └───────┬─────────┘
                ▼
        ┌───────────────────────────┐
        │  우리 백엔드 (관리형/BaaS)   │
        │  - 인증/권한(멀티테넌트)     │
        │  - 출퇴근/근태/리포트 로직   │
        │  - 실근무시간 산출          │
        │  ┌─────────────────────┐   │
        │  │ GaonFR 어댑터(내부)  │──HTTPS──▶  [사내 얼굴서버 GaonFR]
        │  └─────────────────────┘   │        (얼굴 등록/인식/검출·원본 보관)
        └───────────┬───────────────┘
                    ▼
        [관리형 DB]  (참조·기록만, 얼굴 원본 없음)
```

- **얼굴 원본·특징값은 GaonFR에만.** 우리 DB는 참조·기록·집계만 → 생체정보 보관 부담을 위탁.
- 관리형(BaaS) 선택으로 서버·DB 운영 부담 최소화(비개발자 친화, 파일럿 적합).

## 2. 핵심 데이터 흐름

### 2-1. 얼굴 출퇴근 (본인확인 + 위조방지)
```
[출근] → nonce 발급 → 실시간 촬영(업로드 차단) → (GPS 동시확인) →
백엔드 → GaonFR 어댑터 recognize → 본인+임계값+얼굴1명 판정 →
통과 시 attendance_record 저장(face_ok=true) → 완료요약
실패/장애 → 재촬영 → 연속 실패 시 GPS 폴백
```

### 2-2. GPS 출퇴근 (대체수단)
```
[출근] → 위치 취득(accuracy) → 지오펜스(사업장 반경) 판정 → (보조: IP 등) →
반경 이내 → attendance_record 저장(gps_ok=true) → 완료
반경 밖/권한거부/위조의심 → 안내·재시도 → 필요 시 관리자 수동보정(로그)
```

### 2-3. 옵션 B 자리확인 (실근무시간)
```
근무 중 주기(10~15분) → 짧게 촬영 → detect(신원식별 X) → present(있음/없음)만 저장 →
일 마감 시 worktime_daily 집계(실근무 = 재실 − 자리비움)
```

## 3. 공통(횡단) 관심사

| 항목 | 방침 |
|---|---|
| 멀티테넌트 격리 | 모든 데이터는 `company_id`로 분리, 얼굴은 GaonFR `Group`으로 칸막이 |
| 인증·권한 | 관리형 인증. `admin`=회사 범위, `employee`=본인 범위(최소권한) |
| 비밀값 | GaonFR ClientToken 등 env 전용. 소스·문서·로그 미기록 |
| 통신 | 전 구간 HTTPS |
| 생체정보 | 원본 미저장, 별도 동의·파기·이력, 위탁 고지 |
| 위치정보 | 최소수집·이동경로 미저장·목적제한 |
| 보존 | 출퇴근 기록 3년(법정), 파기 이력 감사 보존 |
| 장애 대응 | GaonFR/네트워크 장애 시 GPS 폴백(얼굴 강제 금지) |

## 4. 기술 선택 메모 (확정 아님, 구현 단계에서 구체화)
- 백엔드/DB/인증/저장 = 관리형(BaaS). 구체 벤더는 구현 착수 시 확정.
- 프런트: 웹(관리자 PC + 직원 모바일 웹). 네이티브 앱은 위조방지 강화가 필요할 때 [5] 이후 검토.
- GaonFR 어댑터 = 서버 측 단일 모듈.

## 5. [5] 보안·법무로 넘기는 핵심 판단
- 옵션 B 법적 성격(이미지 미저장이 규제 완화에 충분한지)
- 라이브니스 잔여 위험 수용/네이티브앱·전문엔진 도입 여부
- GPS 원본좌표 보관 여부·기간, IP 보조확인 적정성
- 얼굴 임계값·GPS 반경/정확도 최종치(파일럿 실측 병행)
