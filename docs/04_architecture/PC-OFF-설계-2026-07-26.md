## 1. 사장님 질문에 대한 답부터

**"웹에서 설정 후 실제 PC를 제어하기 위한 설치 프로그램(에이전트)을 개발해야 하는 건가?" → 네, 맞습니다. 반드시 필요합니다.**

- 웹(브라우저)은 보안상 **자기 탭 바깥을 건드릴 수 없습니다.** 브라우저를 꺼버리면 끝이라 PC 잠금·종료가 원천 불가능합니다. (7/15 리서치에서 유휴감지도 같은 이유로 데스크톱 앱 필요 결론)
- 그래서 시프티·에스원도 전부 "데스크탑 프로그램 설치" 방식입니다.
- **역할 분담**: 웹앱 = 관제탑(정책 설정·결재·현황), 에이전트 = 현장 자물쇠(알림·잠금·해제). 좋은 소식은 **7/15에 계획한 실근무 측정 앱과 같은 앱 하나**로 두 기능을 다 한다는 것입니다.

```
[관리자 브라우저]──설정/현황──▶┌──────────────┐
[직원 브라우저]──연장신청/결재──▶│  웹앱(Next.js)  │◀─── 기존 그대로
                              │  + DB(Prisma)  │
                              └──────┬───────┘
                        신규 API 4개(/api/agent/*)
                    정책 내려주기 ▼  ▲ 이벤트 올리기
                       ┌─────────┴────────┐
                       │ PC 에이전트(설치형)  │ ← 신규 개발
                       │ 알림→잠금→해제→기록  │
                       └──────────────────┘
```

## 2. 현행 코드 리서치 결과 (설계의 근거)

| 확인 항목 | 현행 상태 | 설계에 주는 의미 |
|---|---|---|
| 근무일정 | `Company.workStartTime/workEndTime/workDays` + 공휴일(Holiday·CompanyHoliday) 기존재 | 잠금 기준 시간표를 **그대로 조회만** 하면 됨 |
| 연장근무 결재 | `OvertimeRequest`(targetDate·startTime·endTime·status) + 결재선·결재함 완성 | "승인분만 해제"에 필요한 구조 완비 — **무수정, 조회만** |
| 주52 경보 | `overtimeAlertOn/overtimeWarnHours` 기존재 | PC-OFF 한도 경보에 재사용 가능(후순위) |
| 교대근무 | Shift 6종 모델 기존재 | 1차는 표준 근무시간만, 교대 연동은 2차(범위 명시) |
| 인증 | 브라우저 쿠키 세션(30일)뿐 | 에이전트용 **기기 토큰 인증 신규 필요**(쿠키는 앱에서 못 씀) |
| API | server action 위주, /api는 파일업로드 등 5개뿐 | 에이전트용 REST API를 **신규 폴더로 분리**(기존 무접촉) |

**🔴 영향 범위(사규 2조)**: 이 설계는 **전부 추가(add-only)** 입니다. 기존 표 구조 변경 0, 기존 함수 수정 0. 기존 코드에 손대는 곳은 단 2곳 — ①설정 화면에 "PC-OFF" 섹션 추가 ②사이드바에 관리자 메뉴 1개 추가(라벨 4글자 규칙 준수). OvertimeRequest·결재 엔진·실근무 계산은 읽기만 합니다.

## 3. 시스템 설계

### 3-1. DB 추가 (Prisma — 전부 add-only)

**Company에 필드 추가** (회사별 선택형 원칙):
| 필드 | 기본값 | 뜻 |
|---|---|---|
| `pcOffOn` | `false` | PC-OFF 사용 여부(끔이 기본 — 강제 아님) |
| `pcOffMode` | `"lock"` | `lock`(잠금화면) / `shutdown`(전원종료). **잠금 권장** |
| `pcOffDelayMin` | `30` | 퇴근시각 후 유예(분) — 마무리 시간 |
| `pcOffNotifyMins` | `"10,5"` | 잠금 전 알림 시점(분 전, CSV) |
| `pcOffTempUseMin` | `30` | 일시사용 1회 길이(분) |
| `pcOffTempUsePerDay` | `1` | 일시사용 하루 허용 횟수 |

**User에 필드 추가**: `pcOffExempt Boolean @default(false)` — 예외자(대표·전산담당 등) 지정.

**신규 모델 2개**:
```
AgentDevice  — 어떤 직원의 어떤 PC에 에이전트가 설치됐나
  id / companyId / userId / deviceName(컴퓨터이름) / tokenHash(토큰은 해시로만 저장)
  agentVersion / pairedAt / lastSeenAt(마지막 생존신호) / revokedAt(관리자 연결해제)

AgentEvent   — 에이전트가 보낸 사건 기록(감사·소명용)
  id / companyId / userId / deviceId / type(lock|unlock|temp_use|notify|offline…)
  at / meta(일시사용 사유 등) — ※ 입력 내용·화면은 구조적으로 없음
```

### 3-2. 신규 API (webapp `/app/api/agent/*` — 기존 코드 무접촉)

| API | 하는 일 | 인증 |
|---|---|---|
| `POST /api/agent/pair` | 연결(페어링): 직원이 웹 [내 계정]에서 발급받은 **6자리 일회용 코드**(5분 유효)를 앱에 입력 → 기기 등록 + 기기 토큰 발급 | 일회용 코드 |
| `GET /api/agent/policy` | 오늘~내일 정책 내려주기: PC-OFF 켜짐 여부·모드·근무시간표·공휴일·**내 승인된 연장근무**·일시사용 규칙·서버시각(시계 보정) | 기기 토큰 |
| `POST /api/agent/events` | 사건 묶음 업로드(잠금·해제·일시사용 등, 오프라인분 재전송 포함) + 생존신호 겸용 | 기기 토큰 |
| `POST /api/agent/overtime` | **잠금화면에서 바로 연장근무 신청**(기존 신청 로직 재사용 — 결재선·결재함 그대로 탐) | 기기 토큰 |

- 기기 토큰: 발급 시 1회만 평문 표시, DB엔 해시 저장(비밀번호와 같은 원칙, 사규 8조). 기기별 개별 회수(revoke) 가능.
- 정책 응답에 서버시각 포함 → 직원이 PC 시계를 돌려도 잠금 시각 조작 불가.

### 3-3. PC 에이전트 (신규 설치 프로그램)

- **프레임워크**: 7/15 리서치 결론 유지 — **Tauri 또는 네이티브 C#** 중 프로토타입에서 확정(Electron 제외). 1차는 **Windows 전용**(고객 사무직 PC 절대다수), Mac은 2차.
- **내부 구성 6모듈**:
  1. **정책 동기화**: 5분마다 `/policy` 조회 → 로컬 캐시(암호화) 저장. 잠금 중엔 1분마다(승인 즉시 해제 감지)
  2. **판정기**: (근무요일+근무시간+유예+승인된 연장+일시사용) 조합으로 "지금 잠가야 하나" 1분마다 판단
  3. **알림**: 잠금 10분/5분 전 우측 하단 토스트 — "문서를 저장하세요. 연장이 필요하면 지금 신청"
  4. **잠금화면**: 전체화면 최상위 창. 표시: 사유·해제예정시각 / 버튼: **[연장근무 신청]**(내장 미니폼→API) · **[일시사용 30분]**(사유 필수·관리자 기록) · [새로고침(승인확인)]
  5. **이벤트 큐**: 사건 로컬 저장 → 서버 전송(오프라인 시 쌓았다 재전송)
  6. **트레이 아이콘**: 상시 표시 — "이 앱이 보는 것/안 보는 것" 클릭 1번에 확인(신뢰 설계)
- **오프라인 동작(중요한 안전 설계)**: 서버가 안 닿으면 **마지막 캐시 정책으로 동작**, 캐시조차 없으면(첫 설치 직후 등) **잠그지 않음(업무 우선, fail-open)**. 서버 장애가 전 고객 PC 마비로 번지는 것을 원천 차단.
- **한계 정직 고지(영업·약관에도 반영)**: Ctrl+Alt+Del·안전모드·다른 PC 사용까지 막는 건 OS 구조상 불가능. 우리 제품 메시지는 "감옥"이 아니라 **"정확한 기록 + 퇴근 유도"**. (강제 종료 방지 워치독은 2차 검토)

### 3-4. 웹앱 화면 추가 (관리자/직원)

| 화면 | 내용 |
|---|---|
| [환경설정]에 PC-OFF 섹션 추가 | on/off·모드·유예·알림시점·일시사용 규칙·예외자 지정 (기존 설정 화면에 카드 1개 추가) |
| 신규 [PC관리] 페이지(관리자) | 기기 현황(누구 PC·온라인/오프라인·앱버전·연결해제 버튼) + AgentEvent 로그(일시사용 사유 포함) |
| [내 계정]에 "PC 연결" 카드 | 연결코드 발급 버튼 + 내 기기 목록 + 내 이벤트 열람(본인 데이터 열람권) |

### 3-5. 핵심 동작 흐름 (시나리오)

```
정상 퇴근:  17:50 알림 → 17:55 알림 → 18:30(퇴근18:00+유예30분) 잠금 → 다음 근무일 아침 자동 해제
야근 필요:  잠금화면 [연장근무 신청] → 결재자 승인(결재함/밀린결재 현황판) → 앱이 1분 내 감지 → 승인 종료시각까지 해제
결재자 부재: [일시사용 30분]으로 급한 불 → 사유·기록 관리자 노출 → (하루 1회 제한)
휴무일:     출근 시도 → 잠금화면 "오늘은 휴무일입니다" + 같은 신청 경로
```

|---|---|---|---|
| **Phase 0 — 프로토타입** | 테스트 PC 1대: 지정 시각 전체화면 잠금+해제+유휴감지 실험(웹 연동 없음). **프레임워크 확정**이 목적 | 1~2일 | 사장님 PC에서 잠금·해제 시연 |

| **Phase 2 — 에이전트 MVP** | 페어링·정책·알림·잠금·연장신청·일시사용·이벤트. 수동 설치(서명 없음, 사내 테스트용) | 7~10일 | 시나리오 4종 실기기 통과 |
| **Phase 3 — 상품화** | 코드서명(월 $9.99, MS Trusted Signing)·자동업데이트·[PC관리] 화면·주52 경보 연동 | 5~7일+ | 외부 PC 설치 경고 없음 |
| (2차 이후) | 이석 기반 실근무 측정 통합(7/15 계획)·교대근무 연동·Mac·워치독 | — | — |

## 5. 보안·법무 체크(§6 가드레일 대응)

- 수집=상태·시각뿐. 키 내용·화면캡처 코드는 **아예 안 만듦**("할 기능이 없는" 설계). 개인 PC 강제 불가, 회사별 opt-in, 직원 예외 지정, 본인 데이터 열람 제공.
- 취업규칙/동의서에 "PC 사용 제어·활동유무 수집" 항목 필요 → **도입기업용 안내문 템플릿** 제공(노무사 검토 1회 권장, 상품화 전).
- 토큰 해시 저장·기기별 회수·서버시각 기준 판정. 비밀키 하드코딩 없음.

## 6. 구현하지 않을 것 (범위 제외)

- 화면캡처·키로깅·앱 사용목록 수집(신뢰 원칙 위배), 원격조종, 브라우저 차단/사이트 차단(별개 제품 영역), Mac·교대근무·워치독(2차), 1차에서 shutdown 모드(잠금만 — 문서손실 리스크)
