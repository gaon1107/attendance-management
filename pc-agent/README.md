# PC-OFF 설치형 프로그램 (Windows) — Phase 2

근무시간이 끝나면 직원 PC 화면을 잠그는 프로그램. 웹앱(`../webapp`)이 Phase 1에서 열어둔
API 4개(`/api/agent/{pair,policy,events,overtime}`)만 사용하며 **웹앱 코드는 건드리지 않는다.**

- 지시서: [../docs/04_architecture/PC-OFF-개발지시서-2026-07-26.md](../docs/04_architecture/PC-OFF-개발지시서-2026-07-26.md) §5
- 기술: .NET 10 + WPF (외부 라이브러리 **0개** — 통신·JSON·암호보관 모두 윈도우/닷넷 기본 기능)

---

## 실행 방법 (사장님)

`PC-OFF_실행.bat` 더블클릭 → 빌드 후 자동 실행.
프로그램은 창이 아니라 **화면 오른쪽 아래 트레이(숨겨진 아이콘 `^`)** 에 파란 전원 아이콘으로 들어간다.

| 트레이 오른쪽 클릭 메뉴 | 하는 일 |
|---|---|
| 연결 설정... | 서버 주소·컴퓨터 이름 입력, 웹에서 받은 **6자리 연결코드**로 연결 |
| 서버 연결 확인 | 지금 회사 설정(퇴근시각·유예·일시사용·휴일·승인된 연장근무)을 받아와 보여준다 |
| 수집하는 정보 | 근로자 고지 화면 — **무엇을 보내고 무엇을 안 보내는지** |
| 종료 | 프로그램 종료 |

**연결 순서**: 웹 로그인 → [계정] → "내 PC 연결" → [연결코드 발급] → 나온 6자리를 이 프로그램에 입력.

## 지켜야 하는 규칙 (사규)

1. **비밀값 평문 금지** — 기기 토큰을 로그·화면·예외 메시지에 절대 쓰지 않는다. 서버는 해시만 갖는다.
2. **수집 범위 확장 금지** — 화면캡처·키로깅·앱 목록·이석 측정은 지시서 §0에서 **범위 밖**. `PolicyModels.cs`에 없는 항목을 늘리려면 먼저 보고한다.
3. **fail-open** — 정책을 못 받았으면 **잠그지 않는다**. 확신이 없을 때 잠그는 쪽으로 기울지 않는다.
4. **웹앱 무접촉** — `../webapp` 파일을 고쳐야 하는 상황이 오면 멈추고 보고한다.
5. **자유입력 금지** — 일시사용 사유는 회사가 정한 목록에서 고르기만 한다(민감정보 유입 차단).

## 2-B에서 반드시 지킬 것 (2-A 검수에서 나온 약속)

1. **정책 캐시는 반드시 암호화**해서 보관한다(`TokenStore`와 같은 DPAPI 방식).
   [수집하는 정보] 화면이 근로자에게 이미 "암호화해 보관합니다"라고 고지하고 있어, 평문으로 두면 **허위 고지**가 된다.
2. **시각 비교는 글자가 아니라 분(정수)으로.** `"9:00"`과 `"10:00"`은 글자 크기로 비교하면 뒤집힌다.
   `TrayApp.HmToMinutes`와 같은 방식으로 파싱한 뒤 비교한다. (잠금 사고로 직결)
3. **정책 값 검증을 판정기 입구에서 한 번.** `delayMin` 음수, `notifyMins` 0 이하, `mode`가 `"lock"` 외,
   `days`가 2개가 아닌 경우 → 잠그지 않는 쪽으로(fail-open) 처리하고 기록을 남긴다.
   여기서 **`days` / `approvedOvertime`의 null 원소도 걸러낸다** — `PolicyModels.cs`의 `??=` 패턴은
   목록 자체만 막고 목록 안의 빈 칸은 막지 못한다(실측 확인). 그대로 `foreach`를 돌면 앱이 멈춘다.
4. **테스트 모드는 실행 인자 `--test-mode`로만.** 설정 파일(`config.json`)에 두면 직원이 메모장으로
   잠금을 영구 무력화할 수 있다(2-A 검수 치명 지적). 자동 시작 등록에는 이 인자를 넣지 않는다.

## 남은 위험 — 사장님 결정이 필요한 것 (2-A 검수 치명 C-3)

**설치형 앱의 구조적 한계**입니다. 지시서 §0이 워치독(강제종료 방지)을 범위 밖으로 둔 것과 같은 성질이라,
"클라이언트만으로는 못 막는다"는 점을 분명히 해 두고 **서버 쪽 보상 장치**로 메꾸는 것이 정석입니다.

| 구멍 | 지금 상태 | 막는 방법(결정 필요) |
|---|---|---|
| 직원이 `config.json`의 서버 주소를 가짜 서버로 바꾸면 잠금 무력화 | 설정 파일은 직원이 고칠 수 있음 | 설치 시 서버 주소를 `%ProgramData%`/레지스트리(관리자만 쓰기)에 고정 → **Phase 3(설치본)** |
| 같은 계정에서 도는 다른 프로그램이 기기 토큰을 꺼낼 수 있음 | 추가 자물쇠(entropy)로 "한 줄 복호"는 막음. 파보면 뚫림 | 근본 해결 없음(설치형의 한계). 서버에서 기기 즉시 해제로 대응 |
| 작업관리자로 앱을 끄면 잠금이 풀림 | **의도된 동작**(지시서 §0: 워치독 범위 밖, 사장님 결정 A) | 서버 보상 장치 ↓ |
| http 주소면 연결 정보가 같은 네트워크에서 엿보일 수 있음 | 연결 화면에 ⚠️ 경고 표시 | 실제 배포 시 **https 필수** |
| **서브패스 배포 불가** — `https://회사.co.kr/근태/` 형태로는 연결할 수 없음 | 주소에 경로가 붙으면 거부(엉뚱한 곳으로 코드가 나가는 것을 막기 위해) | 서브패스로 배포하려면 `AgentConfig.IsValidServerUrl`과 `AgentApi.TryBuildUrl`을 함께 손봐야 한다. **배포 형태를 정할 때 미리 결정할 것** |

**권고(서버 보상 장치)**: `enabled=true`인 직원의 PC가 근무일 퇴근시각+유예를 지났는데 `lock` 기록을 보내지 않으면
관리자 알림에 띄운다. 클라이언트 방어는 어차피 뚫리므로 **이것이 유일한 실질 방어선**입니다.
→ webapp 수정이 필요하므로 별도 승인 후 착수합니다(2-A~2-D 범위 밖).
